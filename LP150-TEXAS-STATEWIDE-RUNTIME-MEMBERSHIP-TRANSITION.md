# LP150 — Texas Statewide Runtime Membership Transition

LP150 prepares membership transition architecture. LP150 does not transition production membership. LP150 does not deploy. LP150 does not activate.

## Authoritative Inputs

- LP149 runtime identity registry: `data/lp149/runtime-county-registry.json` with expected SHA-256 `0185e7d3aac7965fff83ce7859c829604091284eda96f33669f2d2757c977f22`.
- LP138 current operational baseline: `evidence/lp138/county-geometry-membership-contract.baseline.json`.
- Current production runtime manifest: `assets/location-resolution/gridly-authoritative-county-geometry-v1.manifest.json`.
- LP148 statewide geometry artifacts remain evidence only and are not regenerated by LP150.

## Architecture Audit

The current runtime membership path remains LP138 baseline → deployed 28-county runtime manifest → existing runtime selection. LP149 identity is recognition-only. LP150 records the audit in `reports/lp150/current-membership-architecture-audit.md` and adds no production lookup path.

## Transition Model

The deterministic registry in `data/lp150/membership-transition-registry.json` represents all 254 LP149 identities. Each row keeps identity, certification, Storage/certificate readiness, geometry readiness, current operational membership, candidacy, approval, deployment, activation, blockers, and evidence references separate.

## Candidate Contract

`data/lp150/candidate-membership-contract.json` is empty, deterministic, non-authorizing, non-deploying, and non-activating. Empty is valid and preserves the 28-county operational runtime.

## Sequential Gates

LP150 validates identity, certification, Storage evidence, runtime geometry, membership contract, approval evidence, deployment authorization, and activation authorization. Technical readiness never satisfies approval, deployment, or activation.

## Classifications

The resolver vocabulary is `CURRENT_OPERATIONAL`, `KNOWN_NOT_CANDIDATE`, `CANDIDATE_NOT_APPROVED`, `APPROVED_NOT_DEPLOYED`, `DEPLOYED_NOT_ACTIVE`, `CERTIFICATION_BLOCKED`, `EVIDENCE_BLOCKED`, and `INVALID_CONTRACT_ENTRY`.

## Runtime Preservation and Non-Authorization Boundary

Runtime selection remains unchanged at exactly 28 counties. Candidate entries are not consumed by package retrieval, geometry selection, search, awareness, routing, or address resolution. LP150 is validation/tooling only.

## Deterministic Artifacts and Regression Coverage

Run `npm run build:lp150`, `npm run verify:lp150`, and `npm run test:lp150`. The validation report is `reports/lp150/membership-transition-validation.json`. Repeated builds are expected to be byte-identical.

## Rollback Strategy

Revert LP150 files (`tools/lp150/`, `data/lp150/`, `reports/lp150/`, `tests/lp150-membership-transition.test.mjs`, package scripts, and this document). No runtime deployment or activation rollback is needed because none occurs.

## Remaining Blockers

LP148 has the pre-existing baseline condition: `[LP148] tracked/generated package does not match deterministic rebuild`. LP150 records this and does not repair or modify LP148 artifacts.
