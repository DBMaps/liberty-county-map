# LP168.1 — Canonical Git-Blob Identity Reconciliation

## Root cause

LP168 compared the baseline commit's canonical Git-blob bytes with bytes from the materialized working tree. Git may check out an unchanged text blob with CRLF on Windows even though the repository stores LF. The byte hashes then differed and LP168 incorrectly classified the artifact as `CHANGED` despite an unchanged `HEAD` blob and a clean Git status.

LP167 also regenerated its package identity from `HEAD`. That made historical LP167 evidence depend on every later version of `package.json`; LP168's legitimate command registration therefore invalidated LP167's otherwise correct milestone record.

## Canonical Git-blob governance rule

Tracked protected-artifact status is governed exclusively by canonical Git objects. LP168 reads both `9fce6301eb2ec106dd7dfd217cb96ad892c6102f:<path>` and `HEAD:<path>` with `git show`, hashes those bytes with SHA-256, and compares those hashes. Reports label the authority as `GIT_BLOB`. Working-tree bytes are not read for identity, authorization, readiness, PASS/FAIL, `CHANGED`, or `UNCHANGED` decisions.

This rule is read-only: the auditor invokes no Git command that changes the index or working tree, and it never rewrites protected application files.

## LP167 historical identity handling

LP167 evidence is anchored to the authoritative LP167 commit `a3f92088a038e77f7349ce3cc371a770792697f3`. Its recorded `package.json` identity and reason, `LP167 npm command registration`, are verified against that commit's canonical blob. Later milestone changes at `HEAD` are deliberately distinct and do not rewrite or invalidate the historical record. Current repository identity remains governed by the later milestone that made the change.

## LP168 current identity handling

LP168 compares the fixed pre-LP168 baseline to the canonical `HEAD` blobs. The governed report records baseline and current SHA-256 values, the symbolic current revision `HEAD`, and `authoritativeIdentitySource: GIT_BLOB`. `js/app.js` remains `UNCHANGED`. A genuine committed blob difference remains `CHANGED` and fail-closed safeguards remain intact.

## Regression protections

Automated coverage proves that:

- CRLF working-tree materialization cannot affect governed identity.
- A genuine committed Git-blob change is detected.
- report generation is byte-identical and canonical LF across isolated runs;
- protected artifacts are not written;
- LP167 verifies its historical package identity rather than the current package identity; and
- LP167 and LP168 verification remain deterministic and read-only.
