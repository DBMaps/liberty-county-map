## Evidence and credential boundary

Repository inspection and tests require no credential. The owner capture requires existing Supabase CLI authentication, GitHub CLI authentication with repository metadata access, and the authenticated Supabase Dashboard SQL Editor. Credentials remain in those tools or owner environment. The capture selects only safe project identifiers, names, regions, statuses, workflow/environment metadata, object paths, content lengths/types, policy classifications, and aggregate counts. It does not request API keys, secret values, user rows, object bodies, connection strings, authorization headers, cookies, or raw environment files.

The capture is read-only. It contains no migration, DDL, DML, function invocation, upload, download, delete, deployment, configuration update, secret update, policy change, authentication change, branch change, activation, or launch command. In particular, anonymous write denial is established from policy metadata—not by attempting a write.

## Stage A — consolidated owner capture

From the repository root in PowerShell 7, use the block below. `supabase login`, `gh auth login`, and the read-only database session must already be configured. `$ProjectRef` and `$Repository` are safe identifiers, but the owner must supply the intended values; LP169.1 does not invent them.

```powershell
Set-StrictMode -Version Latest
$ErrorActionPreference = 'Stop'

$ProjectRef = '<OWNER-APPROVED-20-CHAR-SUPABASE-PROJECT-REF>'
$Repository = '<OWNER-APPROVED-OWNER/REPOSITORY>'
if ($ProjectRef -like '<*' -or $Repository -like '<*') { throw 'Replace both owner-approved identifiers.' }

if ((git status --porcelain).Count) { throw 'Start from a clean working tree.' }
& .\tools\lp169\capture-owner-production-evidence.ps1 `
  -ProjectRef $ProjectRef `
  -Repository $Repository

Write-Host "Review only: $env:TEMP\gridly-lp169-owner-review"
Write-Host 'Do not copy the review bundle into Git.'
```

The script's Supabase commands require the existing authenticated Supabase session. Its `gh repo`, `gh workflow`, `gh secret list`, and `gh api` commands require the existing GitHub session. Database catalog evidence is exported from the governed query in Supabase SQL Editor and ingested with the LP169.3 Node command. Results are written beneath `%TEMP%\gridly-lp169-owner-review`, and a SHA-256 manifest records the safe review files. The directory is deleted and recreated on each capture.

The owner must separately approve or classify the canonical production domain, website origin, Supabase site URL, redirect/callback allowlists, CORS origins, Capacitor origin, deep links, support URL, Privacy Policy URL, Terms URL, reporting disclaimer URL, and subscription/refund URL. Until supplied, each remains `UNVERIFIED_OWNER_INPUT_REQUIRED`. Never substitute a guessed URL.

## Stage B — sanitization and deterministic ingestion

After reviewing the safe bundle, create `%TEMP%\gridly-lp169-owner-evidence-draft.json` using schema version 2. Each record may contain only the fields enumerated by `reports/lp169/owner-evidence-requirements.json`. Every `PASS` must be supported by complete evidence; use `SOURCE_UNAVAILABLE` or `OWNER_ACTION_REQUIRED` otherwise. Provenance records the evidence identifier, source, capture method/command family, authentication classification, read-only assertion, redaction state, schema version, completeness, and status.

```powershell
node tools/lp169/ingest-owner-evidence.mjs "$env:TEMP\gridly-lp169-owner-evidence-draft.json"
npm run audit:lp169
npm run certify:lp169
npm run verify:lp169
npm run test:lp169
```

The ingester calculates deterministic content identity, canonicalizes object keys and LF line endings, and writes the governed file only after complete validation. Unknown fields, duplicate identifiers, forbidden value-bearing fields, invalid status/provenance, JWT-like strings, Supabase service-secret patterns, bearer/authorization material, passwords, API keys, tokens, private keys, cookies, and database connection strings cause `SANITIZATION_FAILED`. Rejection is atomic and the input is never echoed.
