# LP169.2 — Windows PowerShell 5.1 Evidence Capture Compatibility

## Observed owner error and root cause

The authenticated owner ran the LP169.1 capture from the authoritative Windows environment. Windows PowerShell 5.1 rejected `-Encoding utf8NoBOM` with `Cannot bind parameter 'Encoding'` because that encoding name is not part of its cmdlet encoding enumeration. This was a script compatibility defect, not an authentication, GitHub, Supabase, or production-readiness finding. No production mutation occurred.

Replacing it with plain `-Encoding UTF8` would be insufficient: Windows PowerShell 5.1 commonly writes a UTF-8 byte-order mark for that setting. Governed JSON requires canonical UTF-8 without BOM and LF, so accepting the cmdlet default would change governed bytes.

## Implementation

The capture now constructs `System.Text.UTF8Encoding($false)` through `New-Object`, which is compatible with Windows PowerShell 5.1 and explicitly disables the BOM. `System.IO.File.WriteAllText` writes canonicalized LF content to a unique same-directory temporary file. Capture occurs in a unique staging directory; only a fully successful bundle is moved to the review path. An existing bundle is backed up during the final swap, restored if publication fails, and temporary paths are removed in `finally` blocks.

Every JSON artifact and the database JSONL artifact uses that one writer. No `Set-Content`, `Out-File`, `Add-Content`, redirection, default text encoding, PowerShell 7-only `utf8NoBOM` enum, or PowerShell 7-only constructor syntax remains in the output path. Repeated equivalent content therefore has byte-identical UTF-8-no-BOM and LF representation.

## Command shims and fail-closed execution

Authenticated `gh` and `supabase` commands are invoked by command name with PowerShell's call operator. Applications, aliases, functions, and session shims—including an owner function that delegates to `npx.cmd --yes supabase`—are accepted without an Application-only `Get-Command` restriction. Before each capture the native exit status is reset, and a nonzero result terminates capture without publishing captured output.

## Safety preservation

The existing field projections remain narrow: secret presence names/statuses and metadata are captured, never credential values. A pre-write safety boundary rejects JWT-like strings, bearer or authorization material, private keys, database connection strings, Supabase secret/service tokens, and cookies. Rejection messages never repeat captured material. The governed evidence ingester remains the final strict sanitizer.

All remote commands remain metadata reads: project, secret-name, function, repository, workflow, permissions, environment, database catalog, aggregate, and storage metadata inspection. The patch does not run a migration, deployment, upload, policy change, storage write, county activation, runtime change, or public launch.

## Exact authoritative Windows validation procedure

From a clean checkout on the LP169.2 branch, in the already-authenticated **Windows PowerShell 5.1** owner session:

```powershell
$PSVersionTable.PSVersion
git status --short
Get-Command gh
Get-Command supabase

$ProjectRef = '<20-character-project-reference>'
$Repository = 'DBMaps/<repository-name>'
$ReviewDirectory = Join-Path $env:TEMP 'gridly-lp169-owner-review'

& .\tools\lp169\capture-owner-production-evidence.ps1 `
  -ProjectRef $ProjectRef `
  -Repository $Repository `
  -ReviewDirectory $ReviewDirectory

Get-ChildItem $ReviewDirectory -File | Sort-Object Name |
  ForEach-Object {
    $bytes = [System.IO.File]::ReadAllBytes($_.FullName)
    if ($bytes.Length -ge 3 -and $bytes[0] -eq 0xEF -and $bytes[1] -eq 0xBB -and $bytes[2] -eq 0xBF) {
      throw "UTF-8 BOM found in $($_.Name)"
    }
    $strictUtf8 = New-Object System.Text.UTF8Encoding($false, $true)
    $text = $strictUtf8.GetString($bytes)
    if ($text.Contains("`r")) { throw "Non-LF newline found in $($_.Name)" }
    [pscustomobject]@{ Name = $_.Name; Sha256 = (Get-FileHash $_.FullName -Algorithm SHA256).Hash.ToLower() }
  }

npm run audit:lp169
npm run certify:lp169
npm run verify:lp169
npm run test:lp169
npm run test:lp168
npm run test:lp167
git diff --exit-code -- js/app.js
git diff --exit-code -- reports/lp162 reports/lp163 reports/lp164 reports/lp165 reports/lp166 reports/lp167 reports/lp168
git diff --check
git status --short
```

Review the temporary bundle without copying it into the repository. Create only the schema-v2, owner-reviewed draft described by `evidence/lp169/README.md`, then invoke its governed ingester. Do not paste authentication status, tokens, passwords, connection strings, headers, or raw command output into evidence or documentation.
