## Governed boundary

The query reads only approved information-schema catalogs, policy/index catalogs, Storage bucket identity, and aggregate Storage object counts. It does not retrieve object names, object content, MIME metadata, authentication rows, credentials, or user data. It contains no mutation or DDL statements.

The ingester uses layered validation: a quoted-field CSV state machine and exact cardinality checks; fatal UTF-8 decoding and JSON parsing; strict metadata and item-field allowlists; primitive field-type and count validation; and context-aware secret-shaped value checks. Raw CSV screening is limited to unmistakable credential formats. Governed identifiers—including `service_role` in `metadata.policies[].roles` and names containing password, token, key, or role—are not credentials merely because of their names. Secret-key payloads, JWTs, credential-bearing connection URIs, bearer and authorization values, secret assignments, private keys, and cookies remain rejected. Output remains deterministically sorted, canonical JSON written by atomic replacement.

A rejection reports only `SANITIZATION_FAILED`; it neither displays the rejected cell nor changes prior governed evidence. For safe rule/path/classification diagnostics without values or excerpts, add `--diagnose-sanitization` before the CSV path.

Dashboard metadata can advance observed schemas, tables/views, columns, routines, constraints, indexes, triggers, policy inventory, Storage bucket identity, and aggregate bucket counts. Aggregate count `508`, if observed, is not by itself proof of 254 exact package names plus 254 exact certificate names. API reachability, Edge Function behavior, secret-name presence, CORS, redirects, anonymous runtime reads, write denial, exact names, hashes, and MIME types remain unavailable unless separately evidenced. No deployment, activation, production write, schema/policy change, or Storage change is authorized.
