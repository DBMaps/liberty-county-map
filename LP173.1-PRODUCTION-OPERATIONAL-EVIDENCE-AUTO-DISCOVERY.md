# LP173.1 — Production Operational Evidence Auto-Discovery

## Audit boundary and truthful result

LP173.1 reuses LP173's fact schema, validation, secret rejection, and LP172.1 protected Git-blob result. It reads only an owner-exported, metadata-only local source. It does not invoke a provider command, inspect environment variables, or capture command output, so tokens and credentials cannot be printed by the collector. Missing provider exports are `SOURCE_UNAVAILABLE`; ambiguous records are `NOT_VERIFIED`; only explicit authoritative records are `MACHINE_VERIFIED`, and only explicit authoritative absence is `NOT_CONFIGURED`.

The committed production-metadata source contains no production claims. Consequently, the committed result is `AUTO_DISCOVERY_NO_EVIDENCE`: the ten eligible monitoring and backup facts are `SOURCE_UNAVAILABLE`. Discovery carries forward the thirteen collected `OWNER_ATTESTED` governance facts from the sanitized LP173 evidence contract, while monitoring ownership remains `OWNER_ACTION_REQUIRED`. LP173.1 never creates `OWNER_ATTESTED` evidence and never infers an owner or authority from Git, repository, plan, platform capability, or account metadata.

## Safe source contract

Copy `evidence/lp1731/production-metadata.template.json` to the ignored `production-metadata.local.json`. Add records only under the eligible `monitoring` and `backup` fields. Each record uses one of:

* `VERIFIED_PRESENT`: requires value, evidence type, source, collection method, and verification method and becomes `MACHINE_VERIFIED`.
* `VERIFIED_ABSENT`: requires the same provenance and becomes `NOT_CONFIGURED`; empty or ambiguous output must never use this status.
* `UNCERTAIN`: becomes `NOT_VERIFIED`, including plan names, generic capabilities, and metadata that does not establish the exact governed fact.

Optional `sourceReportedTime` must come from the source. `sourceArtifactIdentity` is required for completed machine facts and uses a lowercase `sha256:` identity. The source must contain metadata only. Secret-shaped text, token-like text, authorization material, private keys, credential-bearing URLs, and database connection strings fail closed before any output is written; source values are not printed in errors.

## Deterministic merge and conflict policy

Discovery writes `evidence/lp173/owner-evidence.autodiscovered.json` without replacing local owner evidence. Prefill starts with discovery, preserves valid `OWNER_ATTESTED` facts, and preserves existing completed owner facts when discovery has no completion. An inconsistent existing `MACHINE_VERIFIED` fact cannot silently replace discovered completion: prefill fails with the field name. Invalid owner input fails LP173 validation before merge. Unresolved owner input cannot downgrade a machine completion.

## Exact Windows PowerShell 5.1 owner workflow

Run from the repository root. Export only safe project-level metadata using the provider's metadata-only UI or documented metadata-only command, then transcribe that sanitized metadata and exact provenance into the ignored local source. Do not paste raw command output or secrets.

```powershell
Copy-Item -LiteralPath 'evidence\lp1731\production-metadata.template.json' -Destination 'evidence\lp1731\production-metadata.local.json' -Force
notepad.exe 'evidence\lp1731\production-metadata.local.json'
npm run discover:lp1731
npm run prefill:lp1731
npm run build:lp173
npm run test:lp1731
npm run test:lp173
npm run verify:lp1731
npm run verify:lp173
```

Review `reports/lp1731/auto-discovery-summary.json`. `machineVerifiedFields` and `notConfiguredFields` were machine-derived, and `ownerAttestedFields` were explicitly owner-attested. `notVerifiedFields`, `sourceUnavailableFields`, and `ownerActionRequiredFields` remain incomplete and need a better source or explicit owner attestation as appropriate.

## Non-authorization

All six states remain `NOT_AUTHORIZED`: deployment, activation, distribution, public launch, production restore, and production rollback. No operation or protected runtime modification is performed. Protected identity remains the LP172.1 canonical baseline Git blob versus canonical HEAD Git blob comparison; working-tree bytes and CRLF materialization remain ignored.
