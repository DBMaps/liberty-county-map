# LP188.11B protected-validation harness provisioning

## Audit and decision

The repository-wide semantic audit covered tracked paths containing `validate`, `validator`, `runtime`, `protected`, `preview`, `smoke`, `execute`, `execution`, `evidence`, `deploy`, `rehearsal`, `rollback`, `telemetry`, `county`, and `operational`, rather than milestone names alone. It found the following credible candidates:

* `tools/Runtime/Invoke-GridlyRuntimeValidation.ps1` and `tools/Validation/Invoke-GridlySmokeTest.ps1` check repository files and Git state only. They neither address a protected endpoint nor emit LP188.11 county evidence.
* `tools/lp151/validate-statewide-operations.mjs`, `tools/lp153/execute-statewide-operations.mjs`, and `tools/lp155/execute-consumer-evidence.mjs` are deterministic contract/report generators. They are not protected-runtime executors.
* LP167–LP179 tools reconcile production readiness and owner evidence. They do not validate the LP188.5 package cohort, and production-oriented tools are intentionally not adopted.
* `tools/lp1837/invoke-protected-preview.ps1` proves that an owner-controlled Cloudflare Access protected preview has existed and that PowerShell 5.1, Node, and authenticated owner workflows are established. It is a one-time deployment/domain workflow, not a reusable county validator; it must not be rerun or duplicated for LP188.11B.
* LP183/LP185/LP186/LP187 tools generate preview readiness, post-preview reconciliation, activation inventory, and statewide foundation evidence. They do not fetch and identity-check all governed county packages from a protected runtime.
* The many `tests/county-runtime`, address, location, package-resolution, rollback, and telemetry tests provide useful local regression infrastructure, but ordinary unit tests are not protected runtime evidence. No Playwright or Puppeteer dependency or governed browser runner is present.

No existing executable performs the required protected endpoint plus exact 215-county LP188.5 identity validation. The decision-tree classification is **VALIDATOR_CAN_BE_BUILT_FROM_EXISTING_GRIDLY_TEST_INFRASTRUCTURE**: the narrow harness uses the repository's existing Node runtime, native `fetch`, SHA-256 conventions, LP188.5 inventory, and LP188.11 evidence ingestion; it introduces no testing framework and duplicates none of the candidates above.

## Harness and environment contract

The selected executable is `tools/lp18811/protected-validation-harness.mjs`, invoked on Windows by `tools/lp18811/invoke-owner-validation.ps1`. It performs read-only HTTPS `GET` requests to the protected application root and each governed `counties/{FIPS}.json`; it never deploys, activates, writes packages, contacts Supabase, clears restrictions, or changes membership. It fails closed unless all six negative-authority flags, exact wave, exact ordered 215 FIPS, and every LP188.5 SHA-256 identity are supplied.

The supported protected environment is an owner-controlled HTTPS test application protected by Cloudflare Access (or an equivalent gateway that accepts the documented Cloudflare service-token headers). The deployed build must expose the unchanged LP188.5 `counties/*.json` files and a `gridly-protected-build-identity.json` containing exactly `deploymentId`, `buildIdentity`, and `environmentClassification: "OWNER_CONTROLLED_PROTECTED_NON_PRODUCTION"`. The harness compares that runtime document with the supplied expected identities. Owner provisioning remains required because the repository does not establish a currently reachable deployment containing those files or a current service-token policy.

Required process-only environment variables are:

* `GRIDLY_PROTECTED_URL`: HTTPS base URL of the non-production protected application.
* `GRIDLY_PROTECTED_DEPLOYMENT_ID`: safe provider deployment identifier.
* `GRIDLY_PROTECTED_BUILD_IDENTITY`: expected immutable build/artifact identity reconciled by the owner to that deployment.
* `GRIDLY_VALIDATOR_ACCESS_CLIENT_ID` and `GRIDLY_VALIDATOR_ACCESS_CLIENT_SECRET`: temporary least-privilege protected-preview service-token credentials. The endpoint policy must authorize them; neither value is written to output.
* `GRIDLY_EXECUTOR_IDENTITY_REFERENCE`: portable, non-secret reference to separately retained executor evidence.

Missing credentials or other inputs fail closed. Redirects are rejected. Credentials are sent only as request headers and secret-shaped portable output is rejected. Deployment ID, build identity, runtime-document hash, and relative evidence references are safe evidence; credential values and the URL are deliberately omitted.

## Dimension classification

| Dimension | Classification | Harness result |
| --- | --- | --- |
| deployment confirmation | `AUTOMATABLE` | Protected root is reachable and a supplied deployment/build identity is recorded; owner must first reconcile those identities. |
| runtime validation | `AUTOMATABLE` | Every governed package is reachable and byte-identical to LP188.5. |
| regression validation | `EXTERNAL_ENVIRONMENT_REQUIRED` | Existing local suites are not falsely promoted to protected-runtime evidence. |
| consumer validation | `OWNER_OBSERVATION_REQUIRED` | A real approved-user browser/device flow is required. |
| boundary validation | `AUTOMATABLE` | Exact governed FIPS and package identities are enforced; unknown or reordered scope fails. |
| telemetry validation | `OWNER_OBSERVATION_REQUIRED` | Owner must inspect provider/runtime telemetry. |
| rollback validation | `OWNER_OBSERVATION_REQUIRED` | No rollback is authorized or performed by this read-only harness. |
| operational validation | `OWNER_OBSERVATION_REQUIRED` | Requires observation after the other dimensions; no activation is implied. |
| executor evidence | `OWNER_OBSERVATION_REQUIRED` | Harness accepts only a portable reference to separately retained executor identity evidence. |
| independent review | `INDEPENDENT_REVIEW_REQUIRED` | Always emitted `PENDING`; the executor cannot self-certify it. |

The independent reviewer must provide a separate portable artifact identifying the reviewer, reviewed deployment/build identity, wave, exact evidence digest, review outcome, and review time. Only ingestion after that genuine artifact exists may set `COMPLETE`; the harness cannot do so.

## Owner execution and handoff

After the owner provisions the six environment variables above in the current PowerShell process, the complete PowerShell 5.1 invocation is:

```powershell
Set-Location (git rev-parse --show-toplevel)
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\lp18811\invoke-owner-validation.ps1
```

This command contains no fake executable or fake endpoint/token value. The unresolved values are external process environment inputs, so the milestone does **not** claim execution-ready infrastructure. Successful execution writes `evidence/lp18811/execution-results/owner-result.json`, then runs the unchanged LP188.11 build, test, and deterministic verification commands. The evidence uses `gridly.lp18811.protected-validation-evidence.v1` and supplies county FIPS, package SHA-256, package schema, execution/dimension results, executor reference, and pending independent review exactly as the existing ingester requires.

Current state remains 28 operational, 11 restricted, zero newly activated. No execution or protected validation was performed in the Codex/Linux environment.

**Overall classification: `PROTECTED_VALIDATION_EXTERNAL_ENVIRONMENT_PROVISIONING_REQUIRED`.** Owner execution can occur only after provisioning a protected deployment containing the exact packages, binding its deployment/build identities, configuring the service-token policy/credentials, and selecting an executor evidence reference. The next action is for the owner to provision those inputs, run the PowerShell block, retain provider/browser/manual evidence, and return the portable result plus a genuinely independent reviewer artifact.
