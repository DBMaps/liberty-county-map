## Contract mismatch

The browser harness filtered the 56 governed fixtures down to `OPERATIONAL_COUNTY_RESULT_STABILITY`, then hard-coded three assertion names into every result. Only the active-FIPS equality was a complete assertion check. The runtime package hook did not contain the governed SHA-256/length comparison required for certified-artifact stability, and no consumer result fixture was entered or compared. Boundary, fallback, and route-awareness had neither fixtures nor browser steps.

The old `reconcile()` then unioned assertion-name strings across county results and required all six names. This simultaneously caused the reported deterministic `FAIL` and made completion forgeable by adding strings. Reconciliation now uses the contract's explicit Wave 0 ownership and requires a `PASS`, `executed: true`, and non-empty passed evidence checks with references for every Wave-0-owned assertion. Assertion names alone cannot complete anything. Incomplete valid execution evidence is reported as `PENDING`, not as a failed browser execution.

The later LP188.11E dimensions—215-county regression, consumer observation, telemetry, rollback, operational observation, and independent review—remain explicit closure dependencies. Reconciliation does not confuse those dimensions with Wave 0 assertion families. Previously completed deployment, runtime, and package-boundary dimensions remain immutable and must not be rerun.

## Execution consequence

Do **not** rerun the existing browser command: it would repeat the same county-selection dimension and still could not prove the outstanding assertions. First govern the missing exact fixtures and expected results and extend the read-only harness with the actual checks. A later owner execution will be required only for those genuinely outstanding Wave 0 checks (and the precise artifact comparison), without duplicating the completed 28-county selection evidence. No Gridly runtime modification or Cloudflare redeployment is required by this audit.
