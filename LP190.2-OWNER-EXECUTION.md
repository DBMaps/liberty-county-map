# LP190.2 owner execution

LP190.2 restores only byte-identical, owner-verified LP130 payloads. It neither rebuilds gzip streams nor changes runtime membership. The `--certify-twice` operation invokes the existing `certifyCountyPackage` export from `tools/lp104/certify-texas-address-package.mjs` twice without changing that governed certifier.

LP135 remains the certification restriction authority, and LP186 consumes LP135 while explicitly marking these restrictions as requiring owner or external action. LP188/LP189 activation authorization is a separate gate. Consequently, a successful LP190.2 result stops at `READY_FOR_ACTIVATION_RECONCILIATION`: a subsequent owner-governed milestone must reconcile LP134 into LP135 and then rebuild/review LP186–LP189 evidence. It must not infer activation authorization from restored bytes.

Run this single block from the repository root in PowerShell:

```powershell
$ErrorActionPreference = 'Stop'
node scripts/lp1901-owner-remote-payload-recovery-probe.mjs --verify-owner-evidence --json
node scripts/lp1902-restore-governed-payloads.mjs --whatif --json
node scripts/lp1902-restore-governed-payloads.mjs --apply --json
node scripts/lp1902-restore-governed-payloads.mjs --verify --json
node scripts/lp1902-restore-governed-payloads.mjs --certify-twice --json
npm run verify:lp1902
npm run test:lp1902
$report = Get-Content reports/lp1902/restricted-county-restoration-recertification.json -Raw | ConvertFrom-Json
$report.counties | Select-Object countyFips, countyName, restorationClassification, @{n='lp134Run1';e={$_.lp134Run1.status}}, @{n='lp134Run2';e={$_.lp134Run2.status}}, lp134Deterministic, restrictionCanBeCleared, remainingBlocker | Format-Table -AutoSize
$report.aggregate | Format-List
git status --short
```

`verify:lp1902` intentionally fails closed until the ignored owner evidence and quarantine payloads exist and all canonical targets have exact governed identities. When identities remain equal, verification preserves the two recorded LP134 results in the handoff matrix.
