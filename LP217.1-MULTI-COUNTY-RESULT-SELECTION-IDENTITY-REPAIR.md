# LP217.1 — Multi-County Result-Selection Identity Repair

## Acceptance evidence and scope

The owner’s live Abilene reproduction searched for **Abilene**, clicked **Taylor County**, displayed **Selected** on both the Jones and Taylor rows, and sent `jones-tx` into the otherwise coherent LP217 transition. Midland → Midland County remained the positive live control. Browser `requestAnimationFrame` warnings of 277 ms and 341 ms are preserved as performance evidence only; this milestone does not optimize them. No post-repair browser pass is claimed here.

## Read-only production trace and root cause

1. `resolveGridlyManualAwarenessAreaSearch` expands an exact canonical multi-county result into one group/result per governed candidate. Each result already retained `canonicalResolution`, the common `place-<GEOID>` value, and its distinct `requestedOperationalCountyId`.
2. `buildGridlySettingsAwarenessOptionsHtml` rendered the rows, but its old selected comparison was `community.value === pendingValue || community.key === pendingArea?.key`. Both county rows share those canonical values, so both received `is-pending` and **Selected**.
3. The click handler saved only `button.dataset.gridlyManualAwarenessValue`. It discarded the row’s existing `requestedOperationalCountyId`.
4. The apply handler then used `flatMap(...).find(community => community.value === pendingValue)`. Because both rows had the same canonical value, `find` returned the first membership (Jones for Abilene). Taylor’s identity was therefore not lost in result construction or LP217; it was ignored at the result-selection write and replaced by first-match reconstruction at apply.
5. The selected-area card was correctly canonical and county-neutral for presentation, but the old pending state behind it lacked operational membership authority.

## Repair and contract

The manual result row now carries its existing governed `requestedOperationalCountyId` in `data-gridly-manual-awareness-county-id`. Pending state retains both the canonical result value and that county ID. The shared comparison requires both fields for canonical multi-county results, while preserving the existing value comparison for ordinary results. Rendering, pending-card resolution, and apply lookup all use that same comparison. Apply passes the matched row’s county unchanged to `gridlySaveCanonicalMultiCountyPlaceHome`.

The operational identity is now:

```text
canonical awareness key / PLACE GEOID + requested operational county ID
```

The card may still say **Abilene — Multi-county community**. Its pending row retains `taylor-tx` or `jones-tx`. A missing county matches no canonical membership, so ambiguity continues to fail closed. No label lookup, membership ordering, registry ordering, county special case, or downstream LP217 propagation changed.

- The statewide governed inventory remains 2,058 memberships. LP216 tracing remains available at `window.gridlyTransitionTrace`, and LP217’s explicit-membership validation remains unchanged.
