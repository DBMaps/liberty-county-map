# LP219.2 — Location Context production evidence source RCA

## Scope and prior evidence

LP219 established a stable governed identity, lifecycle, eligibility, and publication model. LP219.1 then separated the rendered DOM observation from its assumed production observation. The owner-observed Pecos state is therefore authoritative evidence for this RCA: three retained/current records, two governed-active records, and the rendered text `3 active issues nearby`. This milestone adds read-only tracing only; it does not certify a new owner browser replay.

## Exact production path

1. The DOM target is `[data-v2-location-awareness="meta"]` / `#mobileAwarenessPanelCrossings` within `[data-v2-location-awareness="panel"]`.
2. `normalizeGridlyMobileAwarenessPanelSummary()` creates `crossingsLine` as `${activeIssueCount} active issue(s) nearby`.
3. Its immediate value is `activeIssueCount`.
4. `activeIssueCount` is the larger of the Alerts grouped count (when positive) and `reconciledActiveIssueCount`.
5. `getGridlyReconciledAwarenessActiveIssueCount()` is the LP214 reconciliation. It returns `Math.max()` across the shared active-issue contract, raw hazard/report/crossing counts, `activeReportsInArea.length`, `activeHazardsInArea.length`, legacy summary count fields, the visible-alert consistency projection, rendered markers, bottom-awareness hazard projection, and a same-county visible-incident audit.
6. The count is copied into the panel dataset as `activeAwarenessCount` by the existing renderer. LP219.1 read that dataset, but incorrectly treated the shared summary arrays alone as the production observer.

Thus the exact source is **an LP214 max reconciliation projection**, not one authoritative collection and not a DOM-derived count. The new audit exposes every operand and the bounded input snapshot. No stale prior integer is used as an operand by this function; asynchronous refreshes can, however, call the projection repeatedly as its source models converge.

## Instrumentation and asynchronous timeline

`window.gridlyLocationContextProductionAudit()` returns the exact source, count, operands, bounded contributor rows, source breakdown, DOM count/parity, last update metadata, generation, and a maximum of 40 ordered events. Each event records timestamp, transition/evidence/provider generations, previous/new counts, source, identities, and update reason. An older transition generation cannot overwrite newer diagnostic state. `window.gridlyGovernedAwarenessAudit()` incorporates the same fields.

Rows are deliberately small and omit raw payloads. Reconciliation order uses the governed stable identity implementation; it never assigns an identity-less item. Results distinguish governed, inactive history, stale, duplicate, unmatched, and identity-unavailable rows.
