# LP234.4 — Canonical Community Alerts Completeness

## Scope and current RCA boundary

LP234.4 adds passive collection-wide evidence for the Austin 19-to-6 observation. The audit reads the governed projection, cached Alerts stage collections, LP223 writer authority, and final DOM identity authority. It does not change DriveTexas radius, LP201 coordinates, county governance, Alerts rendering, crossing rendering, or provider lifecycle policy.

The owner-observed result is classified as **A. LEGITIMATE_GROUPING** only when the runtime audit proves that every governed identity is represented by one of the six final presentation identities. If any identity lacks lineage, the helper instead reports a propagation defect; if the area filter removes an identity, it reports a county-fragmentation defect. The UI count currently means the number of grouped alert presentations, not the number of active governed roadway conditions. Pending owner review, the recommended precise label is **“6 Alert Groups · 19 Active Road Conditions”** when those are the proven runtime values.

Run `window.gridlyLP234AlertsCompletenessAudit()` after Austin and Alerts have reached their stable visible state. Acceptance requires `unaccountedGovernedIds` to be empty, `allGovernedEvidenceAccountedFor` and `overallPass` to be true, `countyFragmentationDetected` to be false, and LP223 writer parity to remain true.

## Deferred product requirement: canonical search result consolidation

Search consolidation is explicitly not implemented in LP234.4. A later milestone must present one result per canonical PLACE identity for city/town searches and one result per canonical county identity for county searches. Austin, Dallas, Katy, Corpus Christi, and Travis County must each appear once; genuinely distinct canonical places with the same name remain separate.
