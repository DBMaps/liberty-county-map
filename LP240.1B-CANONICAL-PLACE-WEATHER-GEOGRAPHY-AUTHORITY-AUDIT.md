# LP240.1B — Canonical PLACE Weather Geography Authority Audit

## Decision

**Weather remains disabled and community-level applicability is not ready.** Gridly can recover Dayton's certified identity and membership from LP239, and the NWS feed can carry authoritative Polygon/MultiPolygon geometry or `affectedZones`. The repository does not contain statewide canonical PLACE polygons or NWS zone polygons at runtime. Therefore it cannot yet truthfully decide whether a current alert applies to Dayton. Unsupported records must fail closed to `UNAVAILABLE`, never `QUIET` or `ACTIVE` via text/radius.

## Exact Dayton identity RCA

Weather reads the thin object returned by `getGridlySelectedAwarenessArea()` (with label/storage value, selected county, awareness radius, and focus coordinates) plus `gridlyGetCanonicalActiveCommunityState()`. That is why it received `Dayton`, `liberty-tx`, awareness area, and selected coordinates, but no PLACE GEOID or governed membership: LP240 read only properties already projected onto those objects and did not invoke the LP239 resolver.

The existing `gridlyResolveCanonicalPlaceGeoid(selected)` bridge resolves that thin county + exact canonical display name against `GRIDLY_COUNTY_REGISTRY[countyId].consumerAwarenessAreas`. For Dayton it returns **4819432**. `gridlyCanonicalCrossingRuntime.lookup({placeGeoid:'4819432'})`, backed by `data/runtime/canonical-crossing-memberships-v1.json`, returns Dayton and governed county FIPS **48291** (Gridly county `liberty-tx`). The LP201 presentation artifact supplies Dayton's authoritative presentation centroid, not a polygon.

LP240 audit instrumentation now invokes those authorities without changing selection architecture. No parallel identity was introduced.

Inventory findings:

* `GRIDLY_COUNTY_REGISTRY` / `gridlyResolveCanonicalPlaceGeoid` owns live canonical identity resolution.
* `canonical-crossing-memberships-v1.json` owns statewide PLACE GEOID → governed county membership and canonical name.
* `gridly-statewide-place-presentation-v1.json` has 1,859 Census-derived representative `lat`/`lon` presentation points. These are centroids/focus points only.
* No committed statewide Census PLACE Polygon/MultiPolygon feature collection, polygon reference, or bounding-box authority exists.
* County boundary artifacts are county authority and cannot substitute for PLACE boundaries. Crossing/membership geometry also cannot substitute.
* The presentation artifact records the certified source as 2025 TIGER/Line Places Texas (`tl_2025_48_place.zip`), but that source ZIP and its PLACE polygon features are not committed. This is the smallest identified source bridge; do not manufacture polygons from centroids.

Dayton PLACE geometry is therefore **unavailable** (`source=null`, `type=null`). All 1,859 canonical PLACEs have the same blocking gap.

## NWS geography inventory

The configured source is the statewide NWS active-alert GeoJSON feed. Provider extraction receives each feature's `geometry` and `properties.affectedZones`. Before this audit normalization used geometry only to derive a representative coordinate and discarded both original geometry and zones. Audit-only bounded metadata now preserves geometry type and affected-zone identifiers without exposing raw polygon payloads.

NWS forms and authority classification:

* Alert `Polygon` / `MultiPolygon`: authoritative for direct PLACE polygon intersection once the canonical PLACE polygon exists.
* `geometry=null` plus `affectedZones`: potentially authoritative only after each NWS zone URL/identifier resolves to an authoritative zone polygon. Identifiers can describe county/public, forecast, or fire zones; the current runtime has no zone resolver/cache and must not infer the zone type.
* `geometry=null` with unresolved/no zones: applicability unavailable.
* `areaDesc`/affected-area text, SAME/UGC text, county/locality string, representative coordinate, centroid, and awareness radius: diagnostic/ranking only, never authority.

Current-alert counts are runtime observations rather than success criteria. The audit helper reports raw count, with/without explicit polygon geometry, affected-zone count, and unresolved IDs.

## Authoritative matching contract

1. **Applies:** a valid NWS alert Polygon/MultiPolygon intersects the full valid canonical PLACE polygon; or a valid, authoritatively resolved affected-zone polygon intersects it.
2. **Does not apply:** at least one supported authoritative alert geography was evaluated against the full PLACE polygon and all evaluated geometries are disjoint. A county name match cannot override this result.
3. **Unavailable:** canonical identity/polygon is missing or invalid; alert geometry is unsupported/null and no affected zone resolves; or evaluation fails. It must not be counted as proof of quiet.
4. A source-wide `QUIET` claim requires a healthy, fresh, complete evaluation in which every in-scope current alert was authoritatively evaluated or authoritatively excluded. Unresolved alerts prevent quiet authority.

The audit fixture evaluator supplies deterministic Polygon/MultiPolygon and resolved-zone intersection capability. It is audit-only and does not publish, poll, promote, or change Weather state.

## Multi-county contract

Canonical PLACE geometry is the primary evaluation domain and must remain whole. The selected governed membership identifies the explicit operational county/context (for navigation, labeling, and fallback), while the complete governed membership list validates that context. It must not clip or truncate the PLACE polygon. Thus an alert intersecting a Katy, League City, or Pearland portion in another valid member county still applies to the selected canonical PLACE. No per-place special case is permitted. A future product decision to evaluate a membership-bounded subarea would require a separately certified geometry and an explicit contract; none exists today.

## Expanded audit helper

`window.gridlyLP240WeatherAuthorityAudit()` now returns identity resolution, all/selected memberships, explicit PLACE-geometry availability, NWS geography counts, zone-resolution availability, evaluation mode, legacy-filter non-authority, intersection results, geography reason, and first geography losing stage. Today the expected mode is `UNSUPPORTED`, with `firstGeographyLosingStage: 'PLACE_GEOMETRY'` after Dayton identity resolves.

## Deterministic capability cases

| Case | Result |
|---|---|
| A Polygon intersects PLACE | applicable |
| B Polygon disjoint | evaluated, not applicable |
| C MultiPolygon intersects | applicable |
| D null geometry + resolved zone | evaluated through zone polygon, applicable |
| E null geometry + unresolved zone | unresolved / unavailable |
| F free-text locality only | unresolved / non-authoritative |
| G centroid/radius only | unresolved / non-authoritative |
| H same large county, disjoint polygon | not applicable |
| I multi-county PLACE | full geometry evaluated; selected membership does not truncate |
