# LP240.1D — Existing community-level spatial authority audit

## 1. Exact RCA

After upstream county/source scoping, **Dayton is distinguished by a circular awareness area centered on Dayton's canonical presentation coordinate, not by a Dayton polygon**. Production resolves the selected anchor, then accepts either (a) a trusted provider point no farther than the radius or (b) a trusted DriveTexas `LineString`/`MultiLineString` whose closest segment is no farther than the radius. For Dayton's existing local selection the anchor is `30.0466, -94.8852` and the configured radius is 8 miles. A canonical statewide PLACE without an explicit radius receives the LP039 default of 7 miles.

Provider city/locality/county/route/title/description text does not win or veto LP039.2 eligibility. Named-road or corridor identity does not bridge an out-of-radius record. County membership supplies upstream county governance but is not the community predicate.

## 2. Exact production predicate chain

1. `gridlyGetLoadedDriveTexasAuthoritySourceRecords` selects the complete connector cache, then provider cache only as a weaker source alternative.
2. `gridlyAdaptDriveTexasRecordsForAuthority` / `adaptOne` preserve stable identity, point coordinates, provider text, and trusted provider GeoJSON.
3. `gridlySelectDriveTexasAuthority` calls `selectedArea`, and `selectedAnchor` resolves canonical PLACEs through `resolveGridlyCanonicalPlacePresentationFocus`; explicit radius wins, focus radius is next, and 7 miles is the default.
4. `buildEligibilityProof` invokes `gridlyQualifyDriveTexasGeometryAuthority.qualify` for every adapted record.
5. `normalizeGeometry` accepts only valid Texas GeoJSON `Point`, `LineString`, or `MultiLineString`. Polygon provider geometry is not part of this road-domain selector.
6. For a point, `qualify` uses haversine distance and the inclusive predicate `distance <= radiusMiles`.
7. For a line, `distGeomPoint` finds the minimum point-to-segment distance. This incorporates a bounds/broad-phase implementation in the LP039 trace and then evaluates segments; the inclusive predicate is again `closestDistance <= radiusMiles`.
8. Geometry wins over the record's representative point: an out-of-radius point can qualify if its trusted line reaches the circle. There is no nearest-community assignment; every candidate community circle may be hit, so circles may overlap.
9. `buildEligibilityProof` additionally requires unique identity, supported category, valid point **or** trusted line, valid anchor, active freshness, and no retained/fallback-only status. Text is not a geographic fallback (`fallbackUsed: false`).
10. `gridlySelectConsumerVisibleDriveTexasSituations` projects only the authority-eligible identities to all consumer surfaces.

### Signal classification and precedence

| Signal | Classification | Production role / precedence |
|---|---|---|
| Governed county membership/geometry | `COUNTY_AUTHORITY` | Upstream scope/context; insufficient for community selection. |
| LP201 coordinate | `PRESENTATION_ANCHOR` | Center of the community circle; not a boundary. |
| Point-to-anchor distance | `DETERMINISTIC_PROXIMITY` | Qualifies at `<= radius`; excludes at `> radius`. |
| Trusted provider road line | `AUTHORITATIVE_NETWORK_GEOMETRY` for DriveTexas | Minimum segment distance to the same circle; can qualify despite an out-of-radius representative point. It is provider condition geometry, not a named-road lookup or municipal boundary. |
| Provider locality/road text | `TEXTUAL_ASSOCIATION` | Preserved for identity/presentation; no eligibility override or veto. |
| Source cache/freshness | non-geographic authority | Complete cache preferred; retained/fallback-only records are rejected from final authority. |

No community polygon, point-in-community-polygon test, selected-area bounds, municipal boundary, or nearest-community winner participates in the final predicate. Bounds are only a line-distance broad-phase optimization. Overlapping circles can associate one condition with multiple communities when each is selected separately.

## 3. Dayton deterministic trace

Fixture: selected `Dayton`, PLACE `4819432`, membership `liberty-tx`, anchor `(30.0466, -94.8852)`, radius `8` miles.

* Point at `(30.0466, -94.8800)`: county scope passes; identity/category/freshness are evaluated; point distance is about 0.31 miles; point predicate passes; ownership is `valid_source_point_inside_awareness_radius_miles`; the consumer projection includes it.
* Point at `(30.25, -94.65)`: even with county text `Liberty`, it is outside 8 miles and is excluded with `outside_awareness_radius_miles`.
* The same distant representative point with provider line `[(-94.89,30.05),(-94.65,30.25)]`: the line reaches Dayton's circle, so `trusted_source_geometry_intersects_awareness_radius` wins and includes it. No route-name/corridor match is involved.

## 5. Existing community geometry inventory

Repository searches across location-resolution assets, community packages, LP190/201/202/213–217/238/239 artifacts, GeoJSON, Census/GEOID fields, contains/intersects, and spatial-index terminology found:

* statewide governed county geometry and PLACE-to-county membership composites;
* 1,859 governed PLACE presentation points;
* provider roadway and TIGER/community road-network line assets;
* specialized regional/service-area artifacts that are not a generic canonical PLACE-boundary authority.

They did **not** reveal a production, statewide canonical PLACE polygon registry consumed by DriveTexas. The LP240 audit therefore continues to report 0 exact PLACE boundaries rather than relabeling county or road geometry.

## 6–8. Roadway role, authority, and Weather reuse

Overall class: `HYBRID_DETERMINISTIC_PROXIMITY_AUTHORITATIVE_NETWORK_GEOMETRY`.

Roadway geometry is the trusted provider condition's complete line, not a generic TIGER corridor selected by matching route text. It measures the closest road segment to the selected community circle. It is legitimate network evidence for a roadway condition, including when the representative point lies outside the circle, but it neither proves that the road segment is inside Dayton's municipal boundary nor assigns all events on a named corridor to Dayton.

Weather decision: **`REUSABLE_FOR_WEATHER_AS_AWARENESS_ONLY`**. The anchor/radius math could support a clearly labeled approximation. The roadway-line branch is domain-specific and Weather hazards are polygons. Neither branch authoritatively proves whether a Weather polygon intersects canonical Dayton.

## 9. Statewide coverage

The selector contract is generic for all 1,859 canonical PLACEs because LP201 supplies presentation coordinates and LP039 supplies a 7-mile default when no explicit radius exists:
