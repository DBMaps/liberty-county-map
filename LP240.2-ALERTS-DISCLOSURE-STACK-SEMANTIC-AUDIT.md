# LP240.2 Alerts disclosure-stack semantic audit

## Scope and conclusion

This is an audit-only milestone. Production rendering, markup, CSS, labels,
sorting, grouping thresholds, disclosure keys and behavior, Show me, Weather,
Community Reports, KBYG, and minimize/restore are unchanged. A passive mounted-model
observer and bounded model fixtures were added. The source-family layer is
**REQUIRED**; the type layer is **CONDITIONAL**; the repeated-road layer is
**CONDITIONAL**; and each condition row is **REQUIRED**.

## 1. Exact production pipeline

1. `getAlertsSurfaceSnapshot()` supplies the authoritative, already filtered
   Alerts snapshot. The authoritative open transaction passes its snapshot and
   `alertsForRender` to `gridlyLP236RenderAlertsPresentation`.
2. `gridlyLP236SourceClass` assigns every input row to one of the fixed LP236
   families. `gridlyLP236BuildModel` creates all three source sections in fixed
   order, classifies family authority, groups rows by condition type, and optionally
   buckets repeated roads.
3. The builder sorts rows by canonical ID, type groups by display label, and
   retains road-bucket insertion order. A road bucket becomes a visible road group
   only when it contains at least two rows **inside the same type group**. Other
   rows are `directRows`.
4. `gridlyLP236RenderAlertsPresentation` emits source `<details>`, type `<details>`,
   optional repeated-road `<details>`, and condition `<article>` elements. The
   authoritative writer mounts that returned HTML, then captures/binds disclosure
   state. There is no condition disclosure.

| Layer | Model | Key / label | Count | identity and order | disclosure / Show me | cardinality |
|---|---|---|---|---|---|---|
| Source family | section | `sourceClass`; fixed label/provenance | `activeConditionCount`, incremented once per accepted input row | family classification; fixed Official, Community, Weather order | active family owns key `sourceClass` and user state; no Show me | zero, one, or many condition identities |
| Condition type | group | canonicalized `conditionType`; `gridlyLP236TypeLabel` | `group.rows.length` | presentation classification, not evidence identity; labels sort locale-wise | owns `${sourceClass}:${conditionType}` and user state; no Show me | one or many identities |
| Road/location | repeated-road bucket | normalized road lowercased under the type; displayed normalized road | `road.rows.length` | `roadName`, `routeName`, then `primaryRoad`; insertion order | owns `${typeKey}:${road.toLowerCase()}` and user state; no Show me | exactly two or more identities when visible |
| Condition | row / `<article>` | canonical ID and condition copy | none on row | canonical ID sort within group/road | no disclosure; condition owns eligible Show me | exactly one governed identity |

## 2. Source-family semantics

`gridlyLP236SourceClass` first respects governed presentation classification,
then bounded provider/kind clues, with Official Roadways as fallback. The fixed
section definitions own source label, provenance, family count, family authority
(`ACTIVE`, `QUIET`, `UNAVAILABLE`), status copy, and deterministic source order.
Only `ACTIVE` is a disclosure; quiet/unavailable is a status row with count zero.
Positive governed rows plus snapshot authority can establish active compatibility;
an empty array alone cannot establish quiet Weather authority. Classification:
**REQUIRED**, because it adds ownership, provenance, authority truth, count, and
source-level navigation not present on individual rows.

## 3. Condition-type semantics

Official Roadways canonicalizes bridge restrictions, lane closures, road closures,
flood/high water, construction/maintenance, and crash/incidents; otherwise it
slug-normalizes the first available provider type field. Community uses that same
fallback field chain and slugging without Official-specific remapping. Weather is
different: its official event display label supplies both canonicalized group key
and label, rather than generic provider `hazard` category.

The type group owns presentation organization, count, disclosure, and alphabetical
label order, but no evidence identity or Show me target. It tells a traveler the
kind and number of conditions before opening individual rows. Where every child
repeats the same type, this information is already recoverable from the rows, so
its unique value is compact scanning/navigation. Classification: **CONDITIONAL**.

## 4. Road/location semantics

Road authority is only `roadName`, `routeName`, or `primaryRoad`, passed through
`normalizeGridlyUserFacingRoadText`; no route is inferred from description copy.
Bucketing occurs for both Official and Community, never Weather, but is scoped
inside a type group and is visible only for two or more same-type rows with the
same normalized, case-insensitive road. A lone road, a missing road, or a road
appearing once in each of multiple types stays on direct condition rows. Therefore
multiple types cannot coexist inside one visible road group, although the same road
can occur in multiple type groups. Road groups retain first-seen road order; their
rows are canonical-ID sorted.

A visible road group adds useful shared location and a local count, avoiding a
road label on each grouped row. It owns disclosure state but never a map target;
Show me remains per condition. Classification: **CONDITIONAL**. Its presence is a
presentation threshold, not a data-semantic requirement.

## 5. Individual-condition semantics

The row owns the original alert object, canonical ID, source index, normalized road,
canonical presentation title/location/condition, safe provider summary, governed
timing/lifecycle copy, Weather details/source, and eligible governed coordinates.
Its `<article>` carries the same canonical ID as both LP236 condition ID and the
delegated alert ID. `gridlyLP236CanonicalId` delegates to the writer identity
authority, falling back through evidence, record, report, incident, and provider
IDs only when that authority is absent. Provider ID is lineage metadata and may
differ from canonical identity; no separate presentation identity is minted.

The condition owns Show me eligibility and action. It owns no `<details>` or open
state. Group construction only places the same row reference into one type group
and then exactly one of a repeated-road group or `directRows`; it neither merges
nor deletes rows. Thus a later visual-only ancestor simplification can preserve
all rows, but only if tests continue proving canonical input-to-DOM bijection.

## 6. Count semantics

For `Official Roadways 2 → Construction 2 → US 90 2 conditions → A, B`:

* source `2` is the number of governed input rows classified Official: **ESSENTIAL**;
* type `2` is the number of those rows classified Construction: **USEFUL**, and
  only numerically identical because every source row happens to share the type;
* road `2 conditions` is the number of rows in the Construction/US 90 bucket:
  **USEFUL**, and identical only because all Construction rows happen to share road;
* there is no row count: A and B are presentation rows for two governed identities.

These are intentionally different parent-scope child counts, not provider-row or
DOM-card-derived counts. Type/road counts become **CONDITIONAL** in singleton or
single-bucket shapes and visually redundant when their scopes coincide, but their
present contract remains truthful and must not be changed in this audit. The global
header total is all governed input rows across families: **ESSENTIAL**.

## 7. Disclosure ownership

Active source, every type, and every visible repeated-road group own native
`<details>` toggles. Conditions own none. Capture and delegated `toggle` binding
maintain three independent sets keyed exactly as described in the table. Rendering
restores those sets once initialized. Default-open policy applies only before user
state exists. There is no accordion or sibling-closing code; opening a sibling does
not close another. Minimize captures and later restores these keys. Removing a
source/type/road visual layer without explicitly migrating its state would remove
that user's control and is therefore contract-risking.

## 8. Show me ownership

The row renderer resolves a target from the alert plus its canonical ID (and
canonical crossing fallback), writes coordinates and the canonical alert ID on the
condition article, and emits a button only for finite coordinates. The delegated
`gridlyLp019BindAlertFocusHandlers` looks up that condition ID, resolves the governed
target, captures disclosure state, minimizes through the sheet lifecycle, and
focuses the map. Source/type/road models have no target and no action. Ancestor
simplification is safe only if the condition article attributes, target resolver,
event delegation, and capture-before-minimize sequence remain intact.

## 9. Identity and deduplication contract

Deduplication occurs upstream in the authoritative Alerts construction/writer
pipeline, not in LP236 grouping. LP236 does not deduplicate: duplicate canonical
input IDs would remain duplicate rows and cause its existing audit to fail. The
canonical condition ID becomes model row ID, `data-gridly-lp236-condition-id`, and
`data-gridly-alert-id`. Provider identity remains on the alert. Type and road keys
are presentation identities only. The passive LP240 helper reports duplicates but
never repairs them. Therefore grouping creates no evidence identity and destroys
none; the protected contract is an input/model/DOM one-to-one identity mapping.

## 10. Weather protected control

Weather uses source → official-event type → direct condition. It never constructs
road groups. On the condition row, identical event/title copy is deliberately
suppressed when it equals the group label, leaving location area, timing, details,
and NWS/provider source. Structurally it feels cleaner because it skips road depth
and suppresses the duplicated child event label, while retaining the governed
condition identity and source/type disclosures. Multiple events create alphabetic
event groups; multiple records for the same event remain separate direct rows.
No Weather behavior or copy changed.

## 11. Community Reports control

Community uses source → provider report type → optional repeated-road group →
condition. Its type mapping is not Official remapping. It uses the independent
community traveler-location resolver and street lineage in condition presentation;
its road may therefore be organizational while the condition's governed submitted
location carries more specific traveler meaning. It can form a road group for two
same-type rows, but a singleton is direct. Show me is condition-owned and requires
a governed target. Official simplification must not be presumed applicable here.

## 15. Complete protected contracts

A repair must preserve: one governed identity per condition; no duplicates or
loss; authoritative upstream filtering and deduplication; fixed source order and
ownership; global/source/type/road count truth; source provenance; all three source
status rows; ACTIVE/QUIET/UNAVAILABLE proof semantics; deterministic type and row
sorting plus road insertion order; exact canonical DOM IDs; stable disclosure keys;
user-owned independent toggles; no sibling auto-collapse; default-open behavior
before user ownership; capture/restore across rebuild and minimize; accessible
summary labels; condition text sanitization and full governed copy; road authority
field precedence and no inferred road; Community location/street authority; Weather
event grouping, title suppression, timing/detail/source, authority reconciliation,
and critical callouts; Show me governed resolution, conditional eligibility,
delegated button contract, physical hit target, focus, minimize/restore; Alerts
writer ownership/failure fallback; KBYG non-interference; and LP236 per-family
identity/count/DOM coverage.

## 16. Candidate repair options (documentation only; no selection)

| option / visible hierarchy | benefits | information lost | contract risks | complexity |
|---|---|---|---|---|
| Keep current Source → Type → optional Road → Condition | zero migration and complete scan hierarchy | none | continued visual repetition | none |
| Source → Road → Condition for Official only | road-first traveler scan; less type stacking | type aggregate/navigation unless encoded on rows | type counts/state/order; roads with mixed types; missing-road bucket; changed keys | high |
| Source → Type → Condition for Official only | removes one disclosure depth | shared-road aggregate/count and road toggle | road state/key loss; repeated route copy | medium |
| Source → Type → Road/Condition with singleton type summary visually folded | reduces one-row repetition | always-visible type count/toggle affordance | conditional DOM/state migration and accessibility | high |
| Preserve all model layers but suppress condition title when exactly equal to type | least structural impact; Weather-like reduction | explicit repeated row type | condition copy expectations and Official/Community snapshot contracts | low–medium |
| Preserve model/counts and render repeated-road label as non-disclosure organization | shallower interaction | road-owned toggle | user road state and minimize/restore contract | medium |

These are analysis candidates, not recommendations. None was implemented.

## 20. Owner passive console block

Run after opening Alerts in a community with active Official Roadways:

```js
(() => {
  const audit = window.gridlyLP240AlertsStackAudit?.();
  if (!audit?.available) return console.info(audit?.message || "Open Alerts first.");
  for (const source of audit.sources.filter((item) => item.sourceCount)) {
    console.group(`SOURCE ${source.sourceLabel} (${source.sourceCount}) [${source.disclosureKey ?? "status-only"}]`);
    for (const group of source.groups) {
      console.group(`TYPE ${group.groupLabel} (${group.groupCount}) [${group.disclosureKey}]`);
      const print = condition => console.log(`CONDITION ${condition.title} id=${condition.conditionId} showMe=${condition.showMeTargetAvailable}`);
      for (const road of group.roadGroups) {
        console.group(`ROAD ${road.roadLabel} (${road.roadCount}) [${road.disclosureKey}]`);
        road.conditions.forEach(print);
        console.groupEnd();
      }
      group.conditions.forEach(print);
      console.groupEnd();
    }
    console.groupEnd();
  }
  return audit;
})();
```

The block reads and prints the passive observer result; it performs no DOM or
state mutation.

## 21–22. Commit and repair-phase recommendation

The audit is committed locally and is not pushed. For the repair phase, first turn
the owner-selected option into explicit per-family acceptance criteria; prototype
Official Roadways only; retain the current model and IDs initially; write migration
coverage for any removed disclosure key before changing markup; and rerun A–J plus
LP236, Weather, Community, Show me, and disclosure/minimize regressions. Weather
must remain the unchanged control and Community must receive an independent owner
decision. No hierarchy option is selected by this audit.
