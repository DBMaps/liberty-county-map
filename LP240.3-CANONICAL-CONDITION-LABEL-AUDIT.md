## 3. Surface contracts and exact trace

### Alerts

* **Official Roadways:** provider category → `gridlyAlertSemanticContract`/LP236 condition type → LP236 road-first model → direct condition title or useful repeated-road disclosure → DOM `.gridly-lp236-condition-title`. The type → road → condition hierarchy remains forbidden.
* **Community:** submitted canonical key → canonical live identity → `gridlyLp0541bCanonicalHazardLabel` → `gridlyLp0541bCanonicalConditionLabel` → canonical presentation → LP236 concise condition → DOM condition title.
* **Weather:** governed weather selection → record `event`/headline/title → LP236 Weather condition type/label → `[data-gridly-weather-event=true]`. Specific provider event wins; `Weather Alert` is fallback only.

### KBYG, popup, Location Context, and other surfaces

KBYG keeps separate concise source families: Weather uses provider event/headline, Official Roadways uses the projected condition/road narrative, and Community uses canonical/community headline models. Popup/detail uses canonical presentation for Community and crossing-specific consumer models for crossings. Location Context and Community Pulse consume governed-awareness projection and policy, then narrative/count models; their counts are not label counts. Search result type text is a classification label and is not presently a canonical condition consumer. Profile/home area, Route Watch, notifications, and historical-intelligence cards consume awareness/story records or summaries; no evidence supports rewriting their internal classification keys in this phase.

Classification: Alerts, KBYG, popup/detail, Location Context, Community Pulse, Route Watch, notifications, history/event cards are **TRAVELER-FACING**. Historical intelligence has its own proven specific-label registry (`Construction → Road Work`, `debris → Debris on Road`, `crash → Crash Reported`) and is therefore an affected competing consumer, not an internal diagnostic. LP audits/debug panels and category review are **DIAGNOSTIC/OWNER-ONLY**. package metadata, lifecycle records, source maps, normalized subtype policy, persistence/disclosure/group keys are **INTERNAL**.

## 5. Protection results

* **IDENTITY GATE:** future display formatting must run after `gridlyResolveCanonicalLiveIncidentIdentity`. It must not write `incidentId`, source/provider/report IDs, `hazardType`, `conditionFamily`, lifecycle state, source kind/ownership, persistence identifiers, or Show-me coordinates/target.
* **Disclosure keys:** LP236 persistence is source/condition disclosure state and presentation grouping uses normalized canonical/provider facts. Any key containing condition type must continue using the canonical type, never the formatted label. Treat this as a repair gate even where a key is session-only.
* **Counts/grouping:** governed projection and LP236 count inputs are record arrays/identity lineage. Presentation grouping uses normalized hazard/category plus title/location in legacy paths, so changing a title too early is a grouping risk. Format only after grouping. No formatter may filter, map-to-unique, or alter group membership.
* **Sort:** source/road/group construction may compare source category, roadway, timing, and presentation text. Apply final label formatting after existing sort to prevent incidental reorder.
* **LP240.2A:** Official Roadways remains road-first; label normalization is allowed only at the leaf condition text.
* **Weather:** provider event precedence is an explicit hard gate; do not feed a specific event through a generic category registry.

## 6. Future authority and precedence

Extend the existing canonical presentation boundary rather than add another context-free title-caser. A source-aware `gridlyConditionDisplayLabel({ sourceFamily, canonicalKey, providerEvent, subtype, existingLabel })` can be called by `gridlyBuildCanonicalLiveIncidentPresentation` and LP236 at their final display boundary. Reuse `HAZARD_TYPES`/subtype options as the Community explicit registry and `gridlyAlertSemanticContract` as Official/crossing semantic evidence; neither alone can own all families.

Recommended precedence: (1) governed specific NWS/provider event intended for display; (2) explicit source-aware Gridly semantic mapping, requiring crossing ownership for `blocked`; (3) configured existing human label; (4) nonblank already-human provider label; (5) safe separator-to-spaces/title-case fallback; (6) honest `Road Hazard`, `Community Report`, `Travel Advisory`, or `Weather Alert` only when source context calls for it. Unknown keys never throw or render blank, and their canonical value remains untouched and available diagnostically.

**SEMANTIC, HIGH CONFIDENCE:** crossing-owned `blocked → blocked_crossing`; approve either established **Crossing Blocked** or candidate **Blocked Crossing**. `traffic_backup → Traffic Backup / Heavy Delay` is already canonicalized in one path.
