# LP241.11 — Zero-Cost Statewide Texas POI Authority

**Evidence date:** 2026-08-28  
**Scope:** Phase A audit and manufacturing design only  
**Production behavior changed:** **No**

## 1. Executive result

The owner-observed proof of concept is sufficient to treat Overture Places as a **promising candidate**, not as a certified statewide authority. The correct provisional classification is **OVERTURE_TEXAS_AUTHORITY_VIABLE_WITH_NORMALIZATION**, coupled with **MANUFACTURING_EXECUTION_REQUIRED**, **LEGAL_REVIEW_REQUIRED**, and **OWNER_DECISION_REQUIRED**. No statewide extract was available or manufactured in this environment, so this milestone deliberately records unknown metrics as `null`/`NOT_EXECUTED` rather than inventing coverage.

## 2. Overture release authority

The manufacturing contract pins owner-tested release `2026-08-19.0`, theme `places`, type `place`, at `s3://overturemaps-us-west-2/release/2026-08-19.0/theme=places/type=place/*`. It never resolves `latest`. The retrieval contract targets DuckDB 1.5.5 and GeoParquet. Independent network validation of this future-dated release and observation of its schema were unavailable; both remain blocking exceptions.

## 3. Texas extraction result

**NOT_EXECUTED.** `extract-texas.ps1` and `extract-texas.sql` provide the exact bounded operation. They dissolve authoritative Census 2025 county geometries whose `STATEFP` is `48`, spatially intersect Places, order by stable Overture ID, and write a Zstandard GeoParquet file under ignored `owner-local/`. This avoids both a global repository asset and rectangle-based neighboring-state contamination. Row count, bytes, partitions touched, and duration remain unknown until execution.

## 4. Schema inventory

The proposed minimum keeps ID, primary name/category, coordinates, county assignment and mapped traveler categories at runtime. Brand, confidence, operating status, address/locality/postcode are useful runtime fields. Alternates, phones, websites, bbox, detailed provenance, and conflation signals remain build-only or omitted. Every source field is marked unobserved pending extraction rather than claiming compatibility with an unseen release.

## 5. 254-county coverage result

All **254** governed county identities and FIPS codes are accounted for deterministically from `data/lp104/texas-counties.json`. Counts and quality metrics are `null`, with `UNKNOWN_NOT_EXECUTED`, until spatial assignment runs against county polygons. Address-string inference is not accepted.

## 6. Community coverage result

All **1,859** canonical Census PLACE anchors are accounted for from Gridly's governed presentation authority. The report also records the governed projection population and multi-county-aware source. Five-, ten-, and twenty-five-mile measures are specified. Thresholds remain pending empirical distributions; POIs are not required to lie inside PLACE polygons. Governed non-PLACE awareness-area measurement remains an execution/design exception because the canonical projection represented here contains the 1,859 PLACE identities.

## 7. Category coverage result

Ten traveler families cover fuel, hospital, emergency care, urgent care, pharmacy, restaurant, grocery, lodging, school, and convenience. The category map is content-hashed. Veterinary, animal hospital, and pet-wellness categories are explicit human-medical exclusions. Alternate categories may add evidence but may not defeat those exclusions; resort records require build review.

## 8. Named business / brand result

Walmart, H-E-B, CVS, Walgreens, Starbucks, and McDonald's have fixed audit rows for raw, probable-parent, child, duplicate, county, and geographic-distribution measures. Values remain unexecuted. The owner evidence supports specific Walmart and H-E-B availability but is not generalized statewide.

## 9. Duplicate / child-POI result

The governed vocabulary is `PARENT_POI`, `CHILD_POI`, `LIKELY_DUPLICATE`, `DISTINCT_POI`, and `AMBIGUOUS`. Walmart Pharmacy, Bakery, Vision, Photo, Auto Care, and Garden Center patterns are child candidates. Coincident identities require proximity plus corroboration such as address, phone, or website. The design performs audit classification only and does not activate production dedupe.

## 10. Confidence / quality result

Candidate thresholds 0.5, 0.7, 0.8, and 0.9 are registered for impact measurement across rural counties, critical categories, brands, and duplicate/junk cohorts. No threshold is recommended before those distributions exist.

## 11. Address / locality quality

Freeform address, locality, region, and postcode completeness are explicit metrics. Gridly may use a spatially assigned county and nearest governed community as **context**, but it must never fabricate street text.

## 12. Normalized Gridly POI schema

The proposal includes `poiId`, display and normalized names, optional brand, primary and Gridly categories, latitude/longitude, optional address/locality/postcode, governed county ID, optional confidence/status, and source. Detailed source records and conflation inputs stay in build evidence.

## 13. Search index architecture options

The size report records: (A) county JSON/JSONL, (B) compressed geographic shards, (C) compact client index, (D) Supabase governed indexes, and (E) hybrid manifests with bounded server search. Final comparison requires measured raw/normalized sizes, mobile memory, cold start, latency, cache behavior, refresh cost, and largest-shard size.

## 14. Recommended search index architecture

The **provisional manufacturing target** is compressed geographic shards plus a small immutable manifest and neighbor/radius expansion. This is not a production selection. It directly prevents a phone from downloading Texas and avoids county hard walls. A measured build must confirm that every individual asset remains below 25 MiB and that dense-area shards are subdivided.

## 15. Package size result

**NOT_EXECUTED.** Texas normalized, gzip, Brotli, average/largest/rural/metro county, and community-radius bytes are all explicitly `null`. The 25 MiB constraint is recorded as 26,214,400 bytes, not treated as evidence that packages comply.

## 16. Geographic packaging result

Resolve the active governed community and county, read the manifest, fetch intersecting spatial shards, add neighbor/radius shards where the search radius crosses a boundary, then search/rank locally and use the existing destination handoff. Multi-county communities resolve the union of memberships; frontier and border searches use radius intersections, not county membership alone.

## 17. Update / refresh pipeline

`PIN → EXTRACT → NORMALIZE → CONFLATE → CATEGORY_MAP → SPATIAL_ASSIGN → PACKAGE → VERIFY → MANIFEST → DEPLOY`. Each manifest carries release/input/tool hashes, row counts, shard hashes and sizes. Stable IDs plus normalized-record hashes drive changes. Only dependent shards/manifests invalidate. Previous immutable manifests enable rollback; stale-release alerts never silently advance the pin.

## 18. Attribution / licensing result

**LEGAL_REVIEW_REQUIRED.** The artifact records Overture's attribution and data-access documentation locations, requires extract-level source notices and build-side provenance, and makes no legal guarantee. Whether notices can be centralized in About/Map attribution and whether derivative/database duties apply must be reviewed against the actual pinned extract metadata.

## 19. OSM supplement result

**INSUFFICIENT_EVIDENCE.** OSM is not automatically combined. A matched spatial/category incremental-coverage audit and ODbL review are prerequisites. Simpler Overture-only architecture remains desirable if executed evidence proves adequate.

2. Texas extraction, county assignment, all coverage metrics, confidence impacts, and size measurements are unexecuted.
