# LP241.12 — Bounded POI Runtime Activation Design

## Executive result

**PHASE_LP24112_RUNTIME_ACTIVATION_DESIGN_CERTIFIED.** This milestone defines a
mechanically bounded, fail-closed integration contract. It does not activate,
deploy, or switch a POI provider. Production POI search remains
`NOT_LAUNCHED_NOT_CERTIFIED`, runtime activation remains `false`, and legal state
remains `LEGAL_REVIEW_REQUIRED`.

## Runtime contract and authority

The only admissible future authority is the 391,772 identity-governed standalone
POIs from LP241.11 D.5. Runtime validation rejects invalid coordinates or required
fields, rejects duplicate IDs and shard conservation failures, and excludes raw
Overture, D.2 review-required records, child POIs, duplicate members, and unresolved
upstream populations. `gridly.poi.runtime.v1` contains only ID, display name,
governed category, coordinates, county context, governed community identity, and
optional brand and counsel-approved provenance summary.

## Shards and search bounds

For a governed PLACE anchor, governed non-PLACE anchor, or explicitly allowed map
center, the resolver validates 5, 10, or 25 miles, calculates the radius bounding
box, enumerates intersected one-degree Texas cells, removes duplicates, and sorts
IDs lexically. Edge cells are included. Fanout is capped at four; excess fails
closed. Search defaults to 10 miles, never exceeds 25 miles or 50 results, and
never offers a statewide query/download. Governed category and bounded text filters
combine with AND semantics; Haversine distance, display name, and ID provide stable
ordering. Invalid coordinates load nothing.

## Identity and presentation

The 1,859 canonical PLACEs and 29 governed non-PLACEs retain their dispositions.
Tarkington is `GOVERNED_NON_PLACE`, `liberty-tx:tarkington`, with a null
`placeGeoid`. A result's structured county context describes its location without
replacing the search community identity. Structured metadata and governed spatial
identity control context. The 149 historical D.4 text-heuristic conflicts remain
structured-reconciliation false positives; freeform address text is descriptive,
never authority, and is not rewritten.

Brand may be displayed when non-empty, but remains
`DESCRIPTIVE_ONLY_NOT_IDENTITY_OR_LAUNCH_AUTHORITY`. Its absence never suppresses a
POI, and it cannot control identity, deduplication, category, or launch eligibility.

## Sparse and zero-result experience

An empty valid query is a successful explicit state: no nearby POIs, no category
match, no text match, or expected sparse-area data. Missing optional brand or
provenance is simply omitted. A failed shard is never disguised as zero results;
regional dependency failure instead falls back to the previous provider with a
diagnostic.

## Gate, diagnostics, delivery, and rollback

The provider gate defaults to the previous runtime and requires all of: explicit
Gridly provider selection, enabled environment, approved release manifest, legal
clearance, exact authority release, and exact schema version. Any absent or
mismatched value fails closed. `gridlyPoiAudit()` is reserved as a bounded audit
surface for provider, release/schema, shard IDs, row/result counts, radius,
community/county context, at most 50 result IDs, fallback/zero reason, and gate
state; it excludes raw metadata and user text.

Delivery uses immutable versioned shard assets and the cache namespace
`gridly-poi/{authorityReleaseId}/{schemaVersion}/{shardId}.json.gz`. A new release
or schema invalidates by namespace. Failed responses are not cached; two bounded
retries use 250 ms and 1,000 ms backoff. Partial loads fail to the previous provider
and cannot claim complete or zero results. No paid dependency is introduced.

Rollback is one provider-gate change to `PREVIOUS_RUNTIME`. New queries immediately
use prior behavior, pending Gridly responses are ignored, versioned cache entries
are ignored (and may be deleted later), no migration occurs, and no user state is
changed. Diagnostics must show the previous provider and inactive runtime.

## Legal-ready hooks

This design makes no legal conclusion. Counsel-approved activation must supply a
map/results attribution surface, About/Legal source and license disclosure, a link
between them, displayed data-source version and authority release ID, an immutable
source-inventory reference, and a counsel-approved release manifest. The legal
gate cannot activate without that external clearance artifact.

## Future activation acceptance plan

Deterministic 5/10/25-mile checks are planned for Dayton, Tarkington, Pecos, Dallas,
Austin, San Antonio, Abilene, Midland, Fredericksburg, Port Arthur, Sulphur Springs,
Huntsville, Eastland, and Cienegas Terrace. The suite covers canonical PLACE,
governed non-PLACE, multi-county context, sparse rural, dense metro, and a
category-specific zero-result case. Every cohort checks identity, bounded fanout,
governed-only IDs, stable ordering, and explicit empty states. Phone testing is a
later, separately authorized prerequisite and was not performed here.
