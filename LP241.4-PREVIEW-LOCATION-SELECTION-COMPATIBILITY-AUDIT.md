# LP241.4 — Preview Location Selection Compatibility Audit

## Decision

**RCA: preview artifact/version skew, not a defect proven in the current application. No runtime repair is authorized or required in this branch.** The protected preview is a manually uploaded, immutable Cloudflare Pages artifact from repository commit `945527f05918dc002742e76de74165e1c8b2ae41` (deployment `458fa7f4-ba68-44c7-82ea-c5e6475e456e`, artifact SHA-256 `c292ce65fd06f5f3265be988fa3fa8d152dbb0309aaf306e799646dd34b56a7f`). It has no Git integration and no automatic deployment. The audited local baseline is `c198159`; therefore localhost and preview are not version-equivalent. The old deployment commit is not present in this shallow repository, so its `index.html`, `app.js`, and service-worker bytes cannot honestly be reconstructed or assigned a script query version.

The preview is protected by Cloudflare Access. Anonymous retrieval from this audit environment returned HTTP 403 and no owner credential was available. Consequently this audit does not fabricate a live desktop, phone, hard-refresh, service-worker-controller, console, or computed-style pass. The owner-observed failure is accepted as live evidence. Current-source behavior is separately deterministic below.

## Exact failed journey

The owner described the traveler-facing **manual awareness/community change** journey: open Settings, expand **My Area**, and use **Find Area** or **Choose from available areas**. The expected chain is:

1. a Settings dock/avatar entry calls `openSettingsSurfaceFromDock`/`openSettingsModal`;
2. `bindGridlySettingsPreferences` binds the search form and manual chooser button;
3. **Find Area** submits `settingsAwarenessAreaSearchForm` to `searchGridlySettingsAwarenessArea`;
4. **Choose from available areas** calls `renderGridlyManualAwarenessAreaPicker`, unhides `settingsAwarenessAreaChooser`, and sets `aria-expanded=true`;
5. selecting a county/community calls `selectGridlySettingsAwarenessArea`; multi-county search confirmation calls `gridlySaveCanonicalMultiCountyPlaceHome` with the selected county identity;
6. the existing awareness synchronization activates the governed area.

On the deployed preview, the journey stopped before step 4: the owner activated the manual change control and no picker appeared on desktop or phone. Current source has a native `button`, a click handler, explicit hidden-state transition, and searchable/selectable UI; it does not depend on hover, pointer-only, touch-only, geolocation permission, Home Area presence, or standalone display mode. A standard button also provides click, touch-generated click, and Enter/Space keyboard activation. The chooser has an accessible name; the Settings dialog supplies dialog semantics and a named close button. No current-source responsive rule is allowed to remove this control.

## Entry-point inventory and failure-state contract

| Entry point | Purpose | Manual fallback status in current source |
|---|---|---|
| First-run onboarding | Use location or enter ZIP/town | Manual form remains beside optional geolocation and focuses after denial/unavailability |
| Settings → My Area → Find Area | Search ZIP/community | Bound submit path independent of geolocation |
| Settings → My Area → Choose from available areas | Browse county-qualified communities | Bound button reveals existing chooser |
| Mobile town chip | Applies My Town map filter | Not the full community-change picker; Settings remains the change path |
| Current-location controls | Geolocation/map/route origin | Not manual community selection |
| Home/Work/Saved Places | Route anchors | Separate from governed awareness selection |
| Destination/address search | Trip destination | Separate from governed awareness selection |

The current manual paths are available for first-time and returning users, with or without Home Area, and when geolocation is allowed, denied, unavailable, or times out. The Settings path does not request location when opened. This audit makes no changes to address/search, routing, trust resolution, or governed identity.

## Desktop, mobile, PWA, and cache result

- **Desktop current source:** deterministic contract passes for click and keyboard-compatible native controls; no live preview pass is claimed.
- **Mobile current source:** deterministic contract passes for touch-compatible native controls and the same Settings handler; no live phone-preview pass is claimed.
- **Geolocation fallback:** first-run manual ZIP/town and Settings manual selection are not conditional on `navigator.geolocation`; denial/unavailability keeps manual input reachable.
- **PWA/cache:** navigation is network-first with `cache: "no-store"` and falls back to cached `index.html` only offline. `js/app.js` is not precached or intercepted. Thus this worker cannot produce new HTML + old app JS through its own app-shell cache. It can retain an old offline HTML shell, but online navigation replaces it. The current worker identifies itself as `lp101.1-runtime-recovery` with cache `gridly-pwa-shell-lp235-v1`; the current HTML requests `js/app.js?v=2403a`. Preview values could not be retrieved through Access and remain unverified.

The proven skew is deployment-level: an immutable 2026 preview upload with automatic deployment disabled versus the current local commit. Re-deploying a reviewed current artifact is an owner/deployment action, not an application-code repair. Do not modify current main to compensate for that stale artifact.

## Production impact and merge recommendation

No production behavior changed. Only this audit and its deterministic regression test are added. Merge is recommended as an evidence/test-only compatibility closure, but **Gridly is not declared launch-ready**. Preview acceptance remains pending until the owner deploys the intended reviewed artifact and performs the first test below.
