# LP241.7 Legacy Dashboard Fail-Closed Launch Safety Repair

**As of:** 2026-08-27  
**Classification:** **OWNER_ACCEPTANCE_REQUIRED** (OA-3 physical Safari smoke remains if required)

## RCA and exact legacy surface

The exposed surface was the original `#dashboardSection.dashboard` inside `main.app-shell.premium-layout`. It owns the historic hero/cards and `.command-center`; its map is a shared implementation dependency. `#gridlyPortraitV2` is the validated mobile presentation owner and `#gridlyDesktopGate.gridly-desktop-gate` is the unsupported-platform owner.

The startup inline selector and `resolveLayoutMode()` independently promoted a portrait viewport at or below 980 CSS px. A resized Windows Edge standalone window therefore selected `portrait`, removed `#gridlyPortraitV2[hidden]` later in startup, and allowed the underlying dashboard to present during the ownership transition. Width and orientation describe window geometry, not a validated mobile input environment.

Exposure paths audited were initial load/reload, delayed prepaint release, app bootstrap/rehydration, window resize, `visualViewport` resize, `ResizeObserver` container changes, orientation change, pageshow restoration, standalone launch, and media-query/display-mode changes.

## Final presentation-authority contract

The validated mobile owner requires all of: portrait orientation, viewport width at or below 980 CSS px, primary coarse pointer, no fine primary pointer, and no hover. All other combinations select the intentional development gate. A missing or failed mobile-owner activation also falls back to that gate. Standalone display mode grants no eligibility.

The legacy dashboard remains an internal DOM/data/map dependency only. It is not a supported traveler presentation. In unsupported environments it is `inert` and `aria-hidden`; the validated shell is deactivated, and the development gate is the sole active owner.

`window.gridlyLP2417PresentationSafetyAudit()` reports the selected authority, display/pointer/viewport signals, visibility, focusability, accessibility exposure, acceptable owner count, and pass/fail.

## Regression result

Deterministic tests cover validated coarse-pointer portrait mobile; desktop and narrow portrait fine-pointer Windows; standalone-equivalent width-independent behavior; both resize directions; landscape/orientation reevaluation; hover/pointer authority; inert/ARIA exclusion; audit-helper pass terms; and prohibition of production claims that the legacy dashboard is supported.
