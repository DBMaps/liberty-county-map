## 23. OA-1 owner-test simplification

### 1. Why OA-1 can be simplified
The owner has already proved that Windows Narrator enters Gridly and receives exposed semantics by hearing “Route search action group.” That observation is not full Narrator acceptance, but it removes any need to transcribe dozens of Tab stops. Rendered order, names, hidden/inert state, overlay leakage, tabindex policy, native keyboard paths, and deterministic focus contracts are objective machine checks. Narrator is retained only at the browser/AT boundary.

### 2. Deterministic keyboard result
**DETERMINISTIC_SEMANTICS_PASS, subject to the live command returning `deterministicPass: true`.** The helper projects the current rendered focus sequence (positive tabindex first, then DOM order), exposes the complete inventory as the non-enumerable `focusOrderProjection`, and prints it with `console.table`. It never clicks, focuses, dispatches, submits, reads/writes storage, calls the network, or changes production state. This projection does not claim Edge/Narrator speech or browser behavior beyond the inspected DOM.

### 3. Essential control result
The projection classifies visible focusable controls for Search, Settings, Alerts, My Area/awareness selection, Destination/Route Watch, Community Reporting, and community lifecycle actions when rendered. Essential information may be satisfied by non-map surfaces; exhaustive marker traversal is not an OA-1 requirement.

### 4. Accessible-name result
For each essential visible focusable control the helper resolves, in authority order, `aria-labelledby`, `aria-label`, associated native labels, relevant native `alt`/`value`, selected option text, and text/title fallback. `unnamedEssentialControls` is an exact exception list. Duplicate visible essential category/name groups are reported under `duplicateAmbiguousEssentialNames` rather than repaired speculatively.

### 5. Focus / modal result
Current open `aria-modal` dialogs are inspected for focus entry and for visible background focus leakage. Hidden, `aria-hidden`, inert, computed visibility, zero-layout, and positive-tabindex states are projected. Source regressions separately prove dialog semantics, modal entry, Escape, inert background, and opener/previous-focus restoration. Because the console audit is passive, closed-surface Escape/restoration fields truthfully say `runtimeActivationPerformed: false`; the four physical actions sample that boundary.

### 6. Pointer-only result
Essential visible inline click/pointer/touch authorities and role-based controls are compared with native or focusable keyboard paths. Exact exceptions appear in `pointerOnlyEssentialActions`. Native buttons, links, inputs, selects, textareas, and summaries retain native keyboard activation; the remaining destination-impact generic control has an audited Enter/Space handler.

## 24. OA-1 native Settings activation failure

The owner proved focus was on the classless Portrait V2 native Settings button. RCA found split listener ownership: `bindBottomDockRealButtons()` deliberately returned for the Settings intent without binding it, while a later Portrait V2 bootstrap was the only click-listener authority. The focused production node could therefore be connected, visible, enabled, and named without owning an activation listener. A native Enter-generated click had no Settings action to invoke; the same unbound node also failed Space and pointer click.

The repair makes `bindGridlySettingsActivation()` the idempotent shared authority used by both dock binding paths. It listens only for native `click`; no Enter, Space, Narrator, synthetic-event, or ARIA workaround was added. Bounded audit state records button identity/connection/visibility, listener authority and bind count, keydown/keyup, click provenance, and the attempted/succeeded/failure open outcome. The opener still uses the existing Settings surface lifecycle, including Escape and focus restoration.

**Updated OA-1 classification:** **DETERMINISTIC_SETTINGS_ACTIVATION_REPAIRED / OWNER_EDGE_NARRATOR_RETEST_REQUIRED.** Stop the remainder of the Narrator spot checks until Settings Enter, Space, pointer, Escape, and opener-focus restoration pass on the owner's current Edge deployment.
