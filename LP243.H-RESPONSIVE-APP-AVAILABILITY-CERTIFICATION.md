# LP243.H Responsive Application Availability Certification

## Historical gate and root cause

LP241.7 intentionally allowed only a coarse-pointer, no-hover portrait viewport at or below 980 CSS pixels to select the production Portrait V2 owner. Every other capability/geometry combination selected `desktop`. The first losing stage was the inline prepaint decision in `index.html`: it applied `gridly-desktop-startup-containment` before first paint. Runtime `resolveLayoutMode()` repeated that decision, set `data-layout-mode="desktop"`, deactivated Portrait V2, and exposed the retained beta promotional board. CSS then hid every body child except that board. The promotional surface is therefore retained as historical markup, but no longer owns a reachable responsive mode.

## Protected portrait contract and repair

The repair changes only presentation selection: the existing Portrait V2 application is now the startup and runtime owner for every viewport. No Search ranking, POI, Alerts lifecycle, KBYG, Location Context count, DriveTexas, weather, reporting lifecycle, Home Area, multi-county, notification, Supabase, route, map coordinate, or data authority is changed.

The existing 320/390 phone portrait CSS is untouched. New CSS is additive and can match only landscape orientation or widths of at least 761px. It bounds the existing header/brief/dock/context/sheet surfaces to 760px, keeps the map viewport available behind them, and gives sheets a dynamic-viewport maximum height with retained vertical scrolling. This is containment of the mobile-derived shell, not a tablet or desktop redesign.

## Orientation and portrait regression evidence

Startup and runtime resolve the same owner. Resize, visual viewport resize, and orientation change continue to schedule the existing layout synchronization; the resolver performs no storage, selected-area, alert, search, map, or data mutation. Because both directions retain the same owner, rotation does not deactivate/recreate Portrait V2 or reset open application state. Static regression tests lock the gate boundary, scoped media query, scroll containment, retained promo markup, unchanged state authority, and asset identities.

Programmatic browser checks should verify shell/map bounds, zero portrait horizontal overflow, dock reachability, and open/scroll/close behavior for Search, Alerts, Settings, and Report. Physical-device visual acceptance remains owner-required for browser chrome, touch, safe areas, and actual rotation behavior.

## Remaining post-launch limitations

This milestone does not provide a desktop dashboard, multi-column layout, tablet information architecture, or desktop navigation. Wider screens intentionally receive the centered, portrait-derived application with surrounding map/background. The historical promotional markup and imagery remain in the repository for a separately authorized future use, but are not selected by responsive application authority.
