# LP243.I2.1D1 — OpenFreeMap Dark compatibility evaluation

**Disposition:** bounded audit only; no production activation.  
**Decision:** `REMOVE_DARK_FROM_GRIDLY`.

## 1. Provider contract and official integration

The provider-contract inputs supplied for this milestone say that OpenFreeMap permits commercial use of its free public instance without registration, an account, an API key, or a stated request/view limit. The public service is nevertheless provided as-is, without an SLA or personalized support, and may change or stop. Attribution to OpenMapTiles and OpenStreetMap is required. These statements are current inputs, not a reliability guarantee.

The candidate contract is the documented vector path: the existing Leaflet map remains the owner; `maplibre-gl` renders the official OpenFreeMap Dark style through `@maplibre/maplibre-gl-leaflet`. The style URL to validate at activation time is `https://tiles.openfreemap.org/styles/dark`; no raster URL is inferred. OpenFreeMap's quick-start and service pages could not be independently retrieved in this execution environment (HTTP proxy 403), so endpoint freshness remains an owner-acceptance gate rather than a production-certified fact.

## 2. Dependency design

Neither MapLibre package is currently present in `package.json` or `package-lock.json`. A production candidate would require:

* `maplibre-gl`, including its shipped `maplibre-gl.css`;
* `@maplibre/maplibre-gl-leaflet`, the Leaflet bridge; and
* the bridge's required CSS, if the selected release ships it separately.

Versions are deliberately **not selected in this audit**. Registry metadata was blocked with HTTP 403, and choosing remembered or floating versions would violate the package-governance requirement. A subsequent accepted prototype must resolve and lock exact mutually compatible versions in `package-lock.json`, record compressed and parsed bundle deltas from the actual build, and run license/SBOM review. Package-managed imports are preferable to floating CDN scripts because Gridly already uses npm lockfile governance and Capacitor packaging. No dependencies were added for a rejected, non-activated candidate.

The dependency materially expands the client from raster image loading to a WebGL renderer, worker/runtime code, style evaluation, glyphs, sprites, and vector-tile decoding. CSP would have to allow the documented style/resource origins plus MapLibre worker execution (`worker-src`/`child-src`, subject to the chosen build). A packaged worker is preferable to `blob:` relaxation. This is a meaningful launch/runtime and supply-chain increase for one optional presentation.

## 3. Prototype architecture and Leaflet coexistence

A safe prototype would register one lazy MapLibre-Leaflet layer behind an explicit development flag, with the public identity `Dark`. It would never create a second owning map. Leaflet would retain camera, pan/zoom, `fitBounds`, resize, controls, markers, routes, hazards, crossings, and every feature layer. The bridge layer would occupy only the basemap pane, and its MapLibre instance would be reused while enabled and explicitly removed/disposed when the experiment ends.

Static inspection shows that this is representable in the existing `mapBaseLayersByName` contract: Gridly removes the active registered basemap, adds the selected one, then fires `baselayerchange`. However, the current switching code assumes Leaflet layer add/remove completion is sufficient. It has no MapLibre load/error readiness handshake, WebGL-context disposal assertion, worker/resource failure fallback, or asynchronous attribution reconciliation. Therefore technical coexistence is plausible, but **not certified**; functional compatibility is a FAIL at this milestone's launch-quality evidence threshold.

No prototype was registered in normal runtime. Standard and Satellite configuration, the current `Dark` authority, and `gridlyMapStyleV1` were left unchanged.

## 4. Switching and lifecycle result

The required `Standard → Dark → Satellite → Standard` vector sequence was not runnable because exact dependencies could not be responsibly resolved and installed. Existing raster switching remains unchanged. Consequently there is no defensible proof of:

* unchanged center/zoom and overlays during asynchronous vector load;
* exactly one basemap and attribution;
* absent lingering WebGL canvas/context/workers after switching away;
* absent pointer, pane, z-index, control-rail, resize, or orientation conflicts; or
* deterministic recovery after style, glyph, sprite, or tile failure.

These are acceptance failures, not claims that the bridge necessarily malfunctions.

## 5. Readability and visual fit

Street-name visibility is not accepted on documentation or screenshots alone. No owner-browser render of Liberty County was available, so local street names, major-road labels, shields, density, contrast, nighttime legibility, marker occlusion, and chrome occlusion are unverified. OpenFreeMap Dark therefore scores **MARGINAL** for readability and visual fit rather than inheriting acceptance merely because an official Dark style exists. No custom style was created.

If later reconsidered, the first visual pass should inspect text halo, text color/size, minimum zoom, collision density, and road-shield contrast. Any adjustment would require Gridly to host/version a derived style JSON (and possibly its sprite contract), track upstream schema/style changes, preserve source/data licensing and attribution, and regression-test typography. That maintenance is not justified for an optional mode before the default style itself passes.

## 6. Performance and viewport evidence

No credible visually-usable timing, main-thread stall, request burst, GPU memory, WebGL initialization, switch-away, or switch-back measurement was possible without the renderer and live provider resources. Performance is **MARGINAL**, not PASS. The accepted `390×844`, `932×430`, and `844×390` presentations remain unchanged, but OpenFreeMap rendering at those sizes is **UNVERIFIED**. Physical-device status is also **UNVERIFIED**.

A future experiment must collect navigation timings and a performance trace for initial Dark activation, Dark → Satellite, and Satellite → Dark at all three viewports; count canvases, WebGL contexts, workers, basemap layers, attribution nodes, and requests after each transition; and compare center, zoom, overlay identities, and map dimensions before and after.

## 7. Attribution, network, and privacy

The bridge does not by itself prove that Leaflet's attribution control will consume the style's source attribution. A production candidate must explicitly render the provider-required OpenMapTiles/OpenStreetMap attribution once while Dark is active, remove only that candidate attribution when leaving Dark, and retain the unchanged Standard/Satellite attribution. This audit does not certify rendered attribution, so clarity of the contractual requirement passes but the complete implementation criterion fails; the matrix records **FAIL**.

Expected Dark traffic includes the OpenFreeMap style JSON and the URLs it declares for sprites, glyphs, TileJSON/source metadata, and vector tiles, normally under `tiles.openfreemap.org`; exact hosts must be captured from the fetched style rather than assumed. npm/package acquisition occurs only at build time. No account, cookie, or API key is intended. Normal HTTPS request metadata (IP address, user agent, referrer behavior, requested tile coordinates/zoom, timing, and provider logs) may reveal approximate viewed geography. Gridly must not append user, account, route, report, or device identifiers. Attribution links cause traffic only if followed unless external assets are embedded.

## 8. Capacitor/mobile risk

Risk is **MEDIUM**. MapLibre depends on WebGL, GPU memory, workers, CSS sizing, device-pixel-ratio handling, and a functioning canvas in Android WebView and iOS WKWebView. The bridge must survive `invalidateSize`, orientation changes, background/foreground transitions, WebGL context loss/restoration, safe-area/layout changes, and repeated layer switching without leaking a renderer. Simulator/desktop emulation cannot establish physical-device PASS. A WebGL-unavailable or provider-load failure must fall back to Standard without changing feature authority or persistence into a broken Dark state.

## 9. Provider and implementation risk

Provider/operations risk is **MEDIUM**: no key or fee lowers onboarding risk, while a public instance without an SLA creates outage and change/discontinuation exposure. Standard should be the immediate failure fallback. OpenFreeMap's self-hostable model is an eventual escape hatch, not a zero-cost launch fallback; self-hosting transfers tile generation, storage, bandwidth, updates, monitoring, and incident response to Gridly.

Implementation complexity is **HIGH** relative to the value of one optional basemap. It adds a WebGL renderer and bridge to a mature Leaflet lifecycle, asynchronous readiness/failure handling, extra CSP and resource domains, attribution synchronization, mobile GPU testing, and leak/performance regression coverage.

## 10. Persistence and protected systems

The audit makes no storage change. If removal is authorized, a stored `gridlyMapStyleV1 === "Dark"` must deterministically migrate to `Standard`; all other valid choices remain unchanged. Until that milestone, current behavior is untouched.

Standard, Satellite, map initialization/camera, markers, controls, DriveTexas, crossings, hazards, weather, reports, routes, community awareness, Location Context, Home Area, Awareness Area, POI, Supabase, county governance, KBYG, Search, command trays, and Layers presentation/authority were not modified.

## 11. Decision matrix

| Criterion | Result |
|---|---|
| Functional compatibility | **FAIL** |
| Street/road readability | **MARGINAL** |
| Visual fit with Gridly | **MARGINAL** |
| Performance | **MARGINAL** |
| Mobile/web risk | **MEDIUM** |
| Provider/operations risk | **MEDIUM** |
| Implementation complexity | **HIGH** |
| Attribution/licensing clarity | **FAIL** (contract clear; rendered integration unproved) |

## 12. Final recommendation and rationale

### `REMOVE_DARK_FROM_GRIDLY`

Dark is optional, the current CARTO implementation is launch-unacceptable, and the replacement has not met the indispensable owner-browser readability, attribution, lifecycle, viewport, performance, or physical-device evidence gates. Preserving it would add a second rendering stack and an unsla'd runtime dependency for an unproven product benefit. Removing Dark is smaller, safer, and leaves the accepted Standard and Satellite experience intact.

## 13. Smallest next production milestone

After explicit owner authorization:

1. Remove Dark from the V2 Layers picker and tactical/compact/settings choices.
2. Remove only CARTO Dark construction; retain the frozen Standard and Satellite providers (including the independently used Satellite label layer).
3. Normalize persisted `Dark` to `Standard` before initial basemap resolution and persist the migration.
4. Update selected-state, fallback-index, diagnostics, and layer-control logic for two choices.
5. Remove Dark-only CARTO attribution/dependency only where no other layer uses it; do not remove Satellite labels or their attribution.
6. Add migration, picker, switching, attribution, viewport, and protected-authority regressions.
7. Re-run LP243.I2.1, LP243.H/J/J1, relevant map/layer tests, and owner visual acceptance.

## 14. Owner acceptance steps

There is no runnable OpenFreeMap candidate in normal or flagged runtime, by design. For the removal milestone, the owner should open a clean profile and profiles with each saved style (especially `Dark`), verify the two remaining choices at `390×844`, `932×430`, and `844×390`, cycle `Standard → Satellite → Standard`, confirm correct labels/attribution and unchanged center/zoom/markers/overlays/controls, rotate a physical iOS and Android device, background/foreground the app, and confirm a former Dark preference opens Standard without an error or blank map.
