# LP244.5 — Governed Active Condition Parity

## Root cause and writer/consumer trace

1. The LP219 lifecycle authority projects the active community report into the governed consumer projection. Alerts and KBYG consume that projection and therefore retained the Dayton report.
2. Community ingestion also materializes the report as an `activeHazard`, while crossing governance materializes its FRA-linked view as an `activeReport`. Keeping both representations is intentional: each carries useful hazard or crossing diagnostics.
3. Top Awareness assembled both collections. Its old stable key preferred the hazard's persisted UUID (`id:<uuid>`) but fell back to the crossing identity (`crossing:<fra>:rail`) for the crossing view. The keys could not converge even though the crossing view retained the persisted report under `raw.id`/`latestReport.id`.
4. The Community Awareness summary read only the mutable `activeReports` collection and then independently applied coordinate/text area membership. It did not rejoin the already selected, lifecycle-eligible governed KBYG community projection. During the observed refresh boundary, that collection/filter combination produced an empty `activeReportsInArea` while Alerts and KBYG correctly held the report.
5. Community Pulse was repaired earlier to promote governed KBYG evidence before choosing quiet copy. Awareness Brief still allowed a user-facing-clear Alerts snapshot to zero its inputs without consulting the governed Top Awareness count or authoritative summary. It consequently selected `calm_community_summary` while Pulse selected the active governed report.
6. Location Context retains its existing geographic selector. The parity audit reports its count independently rather than broadening that surface's scope.

## Repair contract

`GRIDLY_GOVERNED_ACTIVE_CONDITION_PARITY_CONTRACT` resolves community representations to `community_report:<persisted-report-id>`. It checks governed/evidence identity first, followed by canonical lifecycle/persisted/source report identity, including nested `raw` and `latestReport` ownership. It never uses display text. Official provider incidents retain an `official:<provider-id>` namespace, and unassociated crossings retain `crossing:<fra-id>`.

Top Awareness now reports raw representation count separately from canonical condition count and duplicate suppression. The Community Awareness writer rejoins selected-area governed community rows before identity deduplication. Awareness Brief cannot enter quiet state while Top Awareness, KBYG evidence, or the authoritative summary has a governed active condition.

The read-only runtime helper is `window.gridlyGovernedActiveConditionParityAudit()`. It returns the selected area, canonical identity sets for each governed surface, raw/canonical/suppression counts, Brief state, Location Context count, and count/identity/Brief/overall parity results.

## Regression lock

`npm run test:lp2445:acceptance` includes the named parity suite in the LP244.5 acceptance path. Fixtures cover the exact Dayton dual representation, two distinct reports, same-copy distinct identities, cleared and stale records, crossing association, official plus community incidents, multi-county qualification, deliberate parity failure detection, and production wiring.

No CSS, visual presentation structure, or Android file is changed by this repair.
