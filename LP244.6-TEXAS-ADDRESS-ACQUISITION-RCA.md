# LP244.6 Texas residential-address acquisition RCA

## Production path and coverage finding

Settings → Travel → Home/Work → Enter Address calls the saved-address integrity contract, the browser `gridlyGeocodingClient`, and the Supabase `gridly-geocode` Edge Function. The default upstream is public OpenStreetMap Nominatim. The function also checks Gridly's governed Texas address foundation/registry and, for eligible rural forms, the US Census range fallback. A legacy Google adapter exists but is disabled unless explicitly configured; LP244.6 adds no provider or paid dependency.

Nominatim is a ranked, data-dependent search index, not a statewide residential-address authority. Public/civic addresses can work while private residences, new subdivisions, rural/FM roads, county roads, and small communities remain uneven. Large-city recall is generally stronger but is not guaranteed. Gridly's owned/governed address packages improve only their built coverage. Therefore safe normalization improves recall, but explicit map confirmation remains required for launch-quality recovery; physical-device checks and live-provider variance remain residual risks.

## Provider request and response audit

The Edge sends `format=jsonv2`, `addressdetails=1`, US country restriction, caller limit (saved addresses request five), optional structured street/city/county/state/postcode/country, and optional viewbox. Free-form saved-address requests preserve the complete typed query. Provider ranking is retained and only bounded to the requested limit; the client validates every returned candidate rather than accepting the first finite coordinate.

The canonical response retains coordinates, display/formatted name, house number, road, village/hamlet community, city/town, county, state, postcode, country, OSM identity, result category/type/class, and bounding box. LP244.6 closes the previous loss of bounding box and explicit provider class/type. Nominatim may omit any field when OSM lacks it.

## Governed acquisition and recovery

At most four attempts are produced: punctuation/whitespace and ZIP+4 normalization, followed by one-token street suffix, rural road, or cardinal-direction expansion/contraction. Every address-verification attempt must retain the supplied city, state, and five-digit ZIP. No retry removes geographic authority. Each attempt requests five candidates, and every candidate passes the LP244.5 Texas containment, state, city, ZIP, and evidence gates.

After no acceptable exact candidate, the app separately queries only the supplied city/state/ZIP to establish a **map anchor**, never to verify or save the street address. Only an anchor candidate passing those same geographic gates can move the map. The old unrelated viewport is not offered. The typed address remains intact; the user moves the map and must press **Set Home Here** or **Set Work Here**.

A confirmed point records `coordinateSource=user_map_selection`, `resolutionStatus=user_confirmed`, `validationStatus=user_confirmed`, original input, anchor source/query/coordinates, confirmed coordinates, and timestamp. Route eligibility requires finite Texas coordinates plus either passed geocoder authority or this complete explicit-confirmation provenance. Cancel/failure never writes storage, so an existing Home or Work remains unchanged and the slots remain independent.

## Acceptance matrix

Permanent contract fixtures cover ordinary, rural FM, county-road, small-community, large-city, suffix, directional and ZIP forms; bare input; wrong city/state/ZIP; multi-candidate retry; no-result fallback; confirmation and invalid confirmation. Existing LP244.5 tests retain legacy Work migration, bad Home quarantine, persistence, Destination Search and Route Preview/Watch wiring. UI source assertions cover cancellation/transaction rollback, Home/Work independence, consumer states, audit evidence, and governed route eligibility.
