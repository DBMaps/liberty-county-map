# LP095.3 — Crossing Alert Runtime Trace

## Objective

LP095.3 adds passive, opt-in runtime evidence for the existing path from a visible **Train Blocking Crossing** alert-card tap through crossing-popup opening. It does not repair or alter the path.

## Interaction path

The trace observes: document click capture → delegated Alerts handler → alert row and rendered-record lookup → alert type and canonical crossing identity → crossing and marker resolution → coordinate resolution → map-focus request and completion → popup request → suppression guards → `marker.openPopup()` request → verified popup-open result.

Every traced event has a sequence number, timestamp, stage, status, and the runtime values available at that exact point. Failed guards and early returns record the return path and final failure stage.

## Instrumentation locations

All instrumentation is in `js/app.js` beside the runtime it observes:

- LP095.3 trace state, immutable snapshots, console recorder, opt-in tap capture, helper, and passive audit.
- `gridlyLp019BindAlertFocusHandlers` for delegated-handler, row, alert-record, alert-type, coordinate, map-focus, and popup-request decisions.
- `gridlyLp0952ResolveCrossingAlertTarget` for canonical identity, crossing lookup, marker lookup, and coordinates.
- `focusGridlyAlertIncident` for map-focus completion.
- `openCrossingPopupFromMarkerInteraction`, `finalizeOpenCrossingPopup`, and `completeVerifiedCrossingPopupOpen` for suppression, open request, visibility failure, and verified open.

## Trace fields

The returned frozen snapshot includes `traceCaptured`, `tapReceived`, `delegatedHandlerEntered`, `alertRowIdentified`, `alertRecordResolved`, `alertType`, `alertId`, `crossingId`, `crossingResolverExecuted`, `crossingRecordFound`, `markerLookupAttempted`, `markerFound`, `markerId`, `coordinatesAvailable`, `coordinates`, `mapFocusRequested`, `mapFocusCompleted`, `popupRequested`, `popupSuppressionEvaluated`, `duplicatePopupSuppressed`, `suppressionReason`, `popupOpenRequested`, `popupOpened`, `popupState`, `failureStage`, `failureReason`, `returnPath`, `completed`, `finalResult`, and an immutable `events` sequence.

`completed: true` and `finalResult: "PASS"` mean a popup open was verified. `finalResult: "FAIL"` includes the exact failure stage, reason, identifiers, popup state, and return path. Values are recorded only where runtime execution reaches the relevant instrumentation; unvisited fields retain their initial value.

## How to run

1. Open Gridly and open browser developer tools.
2. Open the Alerts sheet and confirm a Train Blocking Crossing card is visible.
3. In Console run `window.gridlyLp0953CrossingTrace()` to arm a one-interaction trace.
4. Tap that crossing alert card once.
5. Run `window.gridlyLp0953CrossingTrace()` again to retrieve the frozen captured snapshot.
6. To deliberately discard the prior snapshot and arm another trace, run `window.gridlyLp0953CrossingTrace({ reset: true })`.

The helper never clicks a card, moves the map, opens a popup, or invokes an interaction handler.

## Expected console output

While armed, each reached stage emits a collapsed `LP095.3 TRACE` console group. Expanding it shows the stage name, `PASS` or `FAIL`, and observed values such as alert ID, crossing ID, marker ID, coordinates, popup state, suppression reason, and return path. The last reached terminal group is `Final result` with `PASS` or `FAIL`.

## Interpretation guide

- `tapReceived: false`: the capture observer did not receive a qualifying crossing-card click.
- `delegatedHandlerEntered: false`: the qualifying click did not reach the existing delegated Alerts handler.
- `alertRecordResolved: false`: rendered-alert lookup returned `null`; later fields show whether DOM identity still allowed the existing path to continue.
- `crossingRecordFound: false`: crossing-array lookup returned `null` for the recorded canonical ID.
- `markerFound: false`: the canonical `crossingMarkers` lookup returned `null`. A later general marker search is recorded separately by the map/popup fields.
- `coordinatesAvailable: false`: resolver normalization returned no coordinate pair; the final event records the exact guard return.
- `mapFocusRequested: true`, `mapFocusCompleted: false`: focus was dispatched but its existing completion criteria failed.
- `duplicatePopupSuppressed: true`: `suppressionReason`, `popupState`, and `returnPath` identify the suppression branch.
- `popupOpenRequested: true`, `popupOpened: false`: `marker.openPopup()` was called but no visible popup was verified; retry exhaustion is terminally recorded.

Read the ordered `events` array rather than inferring unexecuted stages from default values.

## Protected systems confirmation

LP095.3 changes no provider data, rendering, marker registry, event routing, delegated-handler behavior, focus behavior, popup behavior, suppression policy, Supabase integration, Community Pulse, Travel Brief, Route Watch, or Destination Intelligence. The capture listener observes a qualifying click and never cancels, stops, or synthesizes an event.

## Historical Intelligence confirmation

Historical Intelligence remains inactive. LP095.3 neither invokes nor activates its runtime. `window.gridlyLp0953RuntimeTraceAudit?.()` reports this trace installation boundary without executing a trace.
