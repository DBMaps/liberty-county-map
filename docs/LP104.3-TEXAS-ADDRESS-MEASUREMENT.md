# LP104.3 — Texas address measurement

## Scope and safety boundary

LP104.3 measures the Texas portion of the official NAD R23 archive before ingestion design. It does **not** ingest records, generate packages, change Gridly Search or route preview, deploy code, or extract the File Geodatabase. `tools/lp104/measure-nad-r23.mjs` is a dependency-free Node.js command which invokes only `ogrinfo -ro`, forces the `OpenFileGDB` driver, and reads `NAD_r23.gdb` directly through GDAL's `/vsizip/` virtual filesystem. Arguments are passed as an array to `child_process.spawn`, so paths containing spaces do not require shell interpolation.

The tool reuses the LP104.2 inspector's explicit archive-path and GDAL-discovery approach. The LP104.2 ZIP64 inventory remains unchanged and can still be run separately. The measurement command checks archive size and modification time before and after all queries, creates reports only after measurement succeeds, and never sends an update, append, overwrite, extraction, or write command to GDAL.

## What is measured

The command first reads the live schema rather than assuming that a release has a fixed field set. `State` and `County` are required. Optional measurement fields are matched case-insensitively and absent fields remain absent from the report rather than being fabricated.

The report contains:

- the complete, bounded national `State` value distribution and the exact observed values selected for Texas;
- Texas counts by the source `County` value, including blank values, plus the selected Liberty County total;
- source-schema state/county/FIPS/GEOID/code-like identifier candidates and their completeness;
- Texas and Liberty completeness counts for available address number, street, locality, ZIP, coordinate, and geometry fields;
- usable-house-number and usable-street combinations, including one-sided records;
- separate counts for observed County Road, County Rd, CR, FM, Farm to Market, Farm-to-Market, RM, Ranch to Market, and Ranch-to-Market patterns;
- unincorporated-community counts and records having `Uninc_Comm` without `Post_City`;
- unique totals and top values for placement, address authority, NAD source, dataset, class, lifecycle, address type, delivery type, and provenance when those fields exist;
- update-date minimum, maximum, and completeness when `DateUpdate` or `LastUpdate` exists;
- normalized candidate checks for both `274 County Road 677, Dayton, TX 77535` and `698 County Road 677`; and
- a conservative national scalability assessment which remains gated on review of the real measurements.

Counts and aggregations execute inside OGR SQLite SQL. Node receives only aggregate rows, county/state groups, capped distributions, and at most 100 target candidates; it never loads the Texas feature set into memory. Source values are retained in output. Normalization is used only for comparisons: trim, case-fold, optional `County` suffix for selecting the proof county, five-digit ZIP comparison, and County Road aliases for the diagnostic.

## PowerShell 5.1 owner run

Run this single block from the repository. It validates Node and the tool, optionally locates QGIS `ogrinfo.exe`, performs the LP104.2 archive inventory/schema inspection, then performs LP104.3 measurement. Set `$OgrInfo` directly if QGIS is installed elsewhere.

```powershell
$ErrorActionPreference = 'Stop'
Set-Location 'C:\GitHub\liberty-county-map'

$Archive = 'C:\GitHub\Gridly-Source-Data\National-Address-Database\NAD_r23.zip'
$Reports = 'C:\GitHub\Gridly-Source-Data\National-Address-Database\reports'
$OgrInfo = $env:GRIDLY_GDAL_OGRINFO
if ([string]::IsNullOrWhiteSpace($OgrInfo)) {
  $OgrInfo = Get-ChildItem 'C:\Program Files\QGIS*\bin\ogrinfo.exe' -ErrorAction SilentlyContinue |
    Sort-Object FullName -Descending |
    Select-Object -First 1 -ExpandProperty FullName
}
if ([string]::IsNullOrWhiteSpace($OgrInfo) -or -not (Test-Path -LiteralPath $OgrInfo -PathType Leaf)) {
  throw 'ogrinfo.exe was not found. Set $env:GRIDLY_GDAL_OGRINFO to the full ogrinfo.exe path.'
}
if (-not (Test-Path -LiteralPath $Archive -PathType Leaf)) { throw "NAD archive not found: $Archive" }
New-Item -ItemType Directory -Force -Path $Reports | Out-Null

node --check .\tools\lp104\inspect-nad-r23.mjs
node --check .\tools\lp104\measure-nad-r23.mjs
node .\tools\lp104\measure-nad-r23.mjs --help
node .\tools\lp104\inspect-nad-r23.mjs $Archive --schema --output (Join-Path $Reports 'lp104.2-nad-r23-inventory.json')
node .\tools\lp104\measure-nad-r23.mjs --archive $Archive --reports $Reports --gdal $OgrInfo --geodatabase 'NAD_r23.gdb' --layer 'NAD' --state 'TX' --county 'Liberty'

Get-ChildItem -LiteralPath $Reports -Filter 'lp104.*nad-r23*' | Select-Object Name,Length,LastWriteTimeUtc
```

If the geodatabase is nested beneath a ZIP directory, use the exact member path reported by LP104.2 for `--geodatabase` (for example `NAD_R23/NAD_r23.gdb`). No archive extraction is necessary or permitted.

## Expected artifacts

The owner-selected reports directory receives:

1. `lp104.2-nad-r23-inventory.json` — LP104.2 source/archive and schema evidence;
2. `lp104.3-nad-r23-texas-measurement.json` — authoritative machine-readable calculated measurements;
3. `lp104.3-nad-r23-texas-measurement.md` — bounded human-readable headline report; and
4. `lp104.3-nad-r23-texas-counties.csv` — deterministic county-by-county counts.

The report timestamp defaults to execution time. For byte-repeatable reruns, supply `--generated-at` with an agreed ISO timestamp. Output filenames and ordering are deterministic; state values are count-ordered, county values are name-ordered, and distribution values use count then value ordering.

## Interpretation and national design constraints

Do not assume `TX` before inspecting exact `State` values; the command inventories values then retains the exact matching Texas source values. Do not use county display name alone as a national key because names can recur in different states. Prefer a complete state-qualified county FIPS/GEOID or equivalent durable NAD identifier, but accept no candidate until the real report proves completeness and collision behavior. Preserve raw values alongside normalized matching keys.

Avoid Texas-specific hard-coding in a future packager: state abbreviations, county suffixes, road aliases, field casing, locality behavior, and schema presence can vary nationally. Deterministic state/county packages appear structurally feasible only if the measured attributes filter completely and durable state/county identifiers prove complete. Spatial filtering should be a validation/fallback mechanism rather than the primary partition key when attribute evidence is adequate.

Liberty County is a reasonable first proof candidate because it exercises rural road aliases, unincorporated communities, and the known target address. It is not approved for package generation until its real completeness, identifier, rural, provenance, and target results are reviewed. The tool intentionally reports `proceedToIngestionDesign: false`; LP104.3 is ready for owner measurement, **not for merge or ingestion approval**.

## Current limitation

The NAD R23 archive and GDAL are not present in the repository environment, so no Texas count, Liberty count, distribution, or target-address result is asserted here. Those facts must come from the owner's local execution. Generated local reports and the source archive must remain outside Git.
