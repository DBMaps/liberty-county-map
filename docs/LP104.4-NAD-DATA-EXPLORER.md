# LP104.4 — NAD data explorer

`tools/lp104/explore-nad-r23.mjs` is a dependency-free Node.js front end to GDAL `ogrinfo`. It reads only the **extracted** NAD R23 File Geodatabase, prints a small console table, and writes matching CSV and JSON reports. It never uses `/vsizip/`, requests counts, performs `GROUP BY`, or benchmarks the dataset. Every record query uses a simple OGRSQL field projection and filter plus an `ogrinfo -limit` (20 by default; maximum 1,000); no aggregate SQL is generated.

The default datasource layer is the real NAD R23 layer, `NAD`. Field names are checked against the real layer schema before querying, and only selected properties are requested. An invalid field exits with the available field names. A zero-row result is successful and produces an empty JSON array plus a header-only CSV.

## Windows PowerShell 5.1 quick start

```powershell
node tools/lp104/explore-nad-r23.mjs `
  "<path to extracted gdb>" `
  --state TX `
  --county Liberty `
  --limit 20
```

This smoke test deliberately relies on the default `NAD` layer and automatic GDAL discovery. Do not recommend merge until it succeeds. Discovery checks `--gdal`, `GRIDLY_GDAL_OGRINFO`, `OGRINFO`, and then `PATH`, in that order. Both a full executable path such as `--gdal 'C:\Program Files\QGIS 3.44.11\bin\ogrinfo.exe'` and a GDAL bin directory are accepted when an override is necessary. Values containing spaces must be quoted in PowerShell. Set `$env:GRIDLY_NAD_GDB = $Gdb` to omit the datasource argument.

## Example explorations

```powershell
$Gdb = 'C:\GitHub\Gridly-Source-Data\National-Address-Database\extracted\NAD_r23.gdb'
$Reports = 'C:\GitHub\Gridly-Source-Data\National-Address-Database\reports'

# First 20 Dayton records.
node .\tools\lp104\explore-nad-r23.mjs $Gdb --state TX --city Dayton --limit 20 --reports $Reports --name dayton-first-20

# Roads containing 677.
node .\tools\lp104\explore-nad-r23.mjs $Gdb --state TX --county Liberty --road '677' --limit 20 --reports $Reports --name liberty-road-677

# Roads containing COUNTY (replace COUNTY with FM or CR for those forms).
node .\tools\lp104\explore-nad-r23.mjs $Gdb --state TX --county Liberty --contains 'COUNTY' --limit 20 --reports $Reports --name liberty-road-county

# House number 274 with a focused field list.
node .\tools\lp104\explore-nad-r23.mjs $Gdb --state TX --county Liberty --house-number 274 --limit 20 --fields Add_Number,StNam_Full,County,Post_City,Zip_Code,Placement,AddAuth,NAD_Source --reports $Reports --name liberty-house-274

# Rural records that identify an unincorporated community.
node .\tools\lp104\explore-nad-r23.mjs $Gdb --state TX --county Liberty --uninc-populated --limit 20 --reports $Reports --name liberty-unincorporated
```

For data-quality spot checks, use `--missing-zip` or `--missing-house-number`. Filters may be freely combined. A contains search can inspect records until it finds the requested small result set; it is not an assertion that the source field has a substring index. This is an exploration utility, not a completeness or certification tool.
