# LP104.4 — TxGIO 2026 county address packages

## Scope and safety

This offline builder reads the official 12,142,647-record TxGIO 2026 statewide File Geodatabase layer `stratmap_2026_address_points_48`. It never opens the GDB for update and writes only beneath the selected output directory. Production runtime is intentionally unchanged.

The maintained `data/lp104/texas-counties.json` manifest maps numeric FIPS to all 254 Texas counties and identifies the existing 28-county Gridly cohort. Therefore the same builder supports Liberty (`48291`), the 28 counties, selected FIPS codes, and a future statewide run without code changes.

Each accepted record has an exact house number, a complete canonical street assembled from the TxGIO street components, a full address, and a point geometry. Records missing any of that evidence are rejected; the builder neither interpolates addresses nor substitutes a nearby road. Coordinates are transformed from EPSG:3857 to EPSG:4326 by GDAL. Compact gzip JSON Lines packages use short runtime-oriented field keys; they are staging artifacts and are **not yet connected to production runtime**.

## PowerShell 5.1 — Liberty certification command

Run from the repository root:

```powershell
Set-Location C:\GitHub\liberty-county-map
$env:GRIDLY_TXGIO_GDB = 'C:\GitHub\Gridly-Source-Data\Texas-Address-Points\Raw\Texas-2026.gdb'
npm run build:lp1044:txgio:liberty -- --gdal 'C:\Program Files\QGIS 3.44.11\bin'
```

The command prints source records read, accepted records, rejected records, duplicates, byte size, and the absolute output path. It atomically creates `liberty-48291.addresses.jsonl.gz`, its JSON certificate, and the statewide package manifest under `data\generated\lp104\txgio-addresses`. A rerun resumes by verifying the package SHA-256 certificate; pass `--force` only to rebuild deliberately.

## Package contract

Each decompressed line is one address with keys: `i` deterministic ID, `h` house number, `r` complete street, `a` full address, `p` postal community, `z` ZIP, `c` county, `f` FIPS, `x` longitude, `y` latitude, `s` source, and `u` source update date. Duplicate deterministic IDs are counted and omitted. County certificates contain counts, output size/path, CRS, and SHA-256 package hash. `manifest.json` indexes all packages produced by that invocation.

The package is ready for data review after the Liberty command succeeds. Runtime integration is a separate LP step and must not begin until Liberty counts, rejections, hash, and representative exact-address queries are certified.

## Read-only exact-address certification

After building Liberty, Denise can certify the original rural Dayton address from PowerShell 5.1 at the repository root:

```powershell
npm run query:lp1044:txgio:liberty -- "274 County Road 677, Dayton, TX 77535"
```

The focused command streams the generated gzip JSONL package without rewriting it. County Road, County Rd, CR, and Co Rd are canonicalized to the same road identity, but a result is printed only when both the house number and canonical road agree exactly. Output includes the outcome (`exact_match` or `truthful_no_result`), exact-match count, normalized query, matched full address, postal community, ZIP, longitude, latitude, and deterministic record ID. A zero-match query prints its truthful outcome, count, and normalized form, then exits unsuccessfully with a clear diagnostic. This certification tooling is not imported by or connected to production runtime.

## Liberty strict exact-address certification

The Liberty evidence reports 51 records on County Road 677, including nearby house numbers 238, 240, 276, and 288, but no house number 274. The maintained certification cases therefore require `274 County Road 677, Dayton, TX 77535` to produce `truthful_no_result` and use `276 County Road 677, Dayton, TX 77535` as an exact-match positive control. The focused test proves that 276 is not returned for 274, a canonical road match alone is insufficient, and neither nearby-number fallback nor interpolation occurs.
