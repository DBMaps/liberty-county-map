# LP104.5 — TxGIO runtime address integration

## Audit first

The destination surface invokes `runGridlyLiveDestinationSearch`, which first renders saved/curated local candidates and then calls `gridlySearchAddress`. That function classifies intent, builds governed address variants, calls the existing `gridlyGeocodingClient` boundary, normalizes candidates, applies LP097/LP101 relevance and containment gates, and hands only the final limited list to the unchanged renderer and route-selection flow. Business search, curated destinations, saved places, the edge provider, and routing therefore share the pipeline but have separate candidate sources.

The smallest safe integration point is the candidate-collection boundary inside `gridlySearchAddress`, after intent/address parsing and before the remote provider loop. At that point an owned exact address point can enter the existing normalization, strict relevance, containment, deduplication, rendering, and route handoff without changing any protected consumer or provider system. An exact package result avoids an unnecessary remote request; a package miss or availability failure leaves the existing boundary behavior intact.

## Runtime design

`gridlyTxgioAddressRuntime` maintains a county registry. LP104.5 registers Liberty only. It does not fetch anything at startup, while typing, for business/place intent, for an incomplete address, or for a query outside registered Liberty context. The first eligible explicit Liberty address lookup fetches only `data/generated/lp104/txgio-addresses/liberty-48291.addresses.jsonl.gz`, decompresses it with the browser gzip stream, validates point records, and indexes exact `HOUSE|CANONICAL ROAD` identities. The promise is reused for later Liberty queries; no other county package is discovered or loaded.

Acceptance requires an exact normalized house-number equality and canonical road equality. County Road/County Rd/Co Rd/CR aliases canonicalize only the road label. There is no number proximity operation, interpolation, road-only candidate, or promotion of an inexact record. Thus 276 County Road 677 is an `exact_match`, while absent 274 is `truthful_no_result` even though 276 exists nearby.

## Browser verification helper

After serving the repository over HTTP and opening Gridly, run this in DevTools:

```javascript
await window.gridlyTxgioAddressRuntime.certification()
```

The returned report must have `passed: true`; its two cases must report `exact_match` and `truthful_no_result`. The evidence must contain one `package_loaded` event (on the first run) and exact lookup events. Network inspection must show no TxGIO request before the helper or an eligible explicit Liberty address search, and only the Liberty package request afterward.
