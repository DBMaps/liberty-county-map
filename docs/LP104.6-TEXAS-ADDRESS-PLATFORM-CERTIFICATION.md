# LP104.6 Texas Address Platform Certification Framework

LP104.6 adds a read-only certification gate; it does not change production search or the LP104.5 runtime. The runner selects a county solely from the runtime manifest, so the same command certifies Liberty or a future Texas county without county-specific rules.

```bash
npm run certify:lp1046 -- --fips 48291 --report reports/liberty-48291-certification.json
```

The manifest entry must identify the gzip JSONL artifact and its runtime certificate. Certification independently checks both declared byte sizes and SHA-256 digests before indexing. It then verifies record identity uniqueness, record FIPS containment, valid exact-address fields, deterministic exact lookups, incorrect-house rejection, invalid input rejection, CR/FM/SH/US aliases, load time, lazy load count, and cache reuse.

The JSON report contains the county, FIPS, package version, bytes, digest, indexed count, exact-match, rejection and normalization statistics, load duration, integrity/load counts, failures, and a final `PASS` or `FAIL`. A failed report makes the command exit nonzero. Package publication must require `PASS`; certificates and artifacts should be immutable and served from versioned URLs.

Sampling is deterministic: records are evaluated in package order and the first `--sample-size` records are used (default 3,000). Incorrect-number cases use deterministic numeric candidates confirmed absent from the road index. Duplicate address keys may legitimately return multiple independently identified source points; duplicate record identities fail certification.
