# LP105.2 — Runtime Address Consumption

Gridly's existing `gridly-geocode` edge boundary now owns Liberty certified-address lookup. The browser sends its normal governed address request; it neither downloads nor parses a county package. Business/place and curated-destination paths are unchanged.

The adapter activates only for a numbered residential request with unambiguous Liberty evidence (Liberty context, or Dayton plus ZIP 77535). Conflicting county, locality, or ZIP evidence makes it ineligible. It validates the checked-in LP104.5 certificate identity, byte length, SHA-256, and strict acceptance claims before inspecting the unchanged gzip package. It retains only records matching the normalized exact house number and canonical road, then passes candidates through the existing LP102 rural acceptance gate and containment checks. Road-only, approximate, interpolated, nearby-number, or conflicting candidates cannot be returned.

The server performs a bounded exact-key scan without building or shipping a browser index. Missing, unreadable, malformed, or mismatched evidence returns `package_unavailable`; the governed provider chain continues. A valid package with no exact record returns `truthful_no_result`, preventing another provider from substituting a nearby address. Development-only response diagnostics record provider outcome, package access, package lookup time, and total invocation time without exposing address data in the UI. Tests also verify that startup, business, curated, and non-Liberty requests avoid package access.

The known Brazoria, Walker, and Washington exact-sample/alias findings and the Harris load-above-5000-ms finding remain unchanged. Later county activation should add a certified identity and explicit eligibility to this server adapter only after its package is certified; it must not add browser datasets or weaken the shared acceptance gate.
