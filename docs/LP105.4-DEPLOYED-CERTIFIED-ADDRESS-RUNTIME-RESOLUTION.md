# LP105.4 — Deployed Certified Address Runtime Resolution

## Audit result

### Verified repository facts

1. The browser uses `js/gridly-geocoding-client.js` to post to the governed `gridly-geocode` Supabase Edge Function. It does not read the address package directly.
2. For an eligible numbered Liberty request, the Edge adapter selects `GRIDLY_CERTIFIED_ADDRESS_BASE_URL`, defaulting to `https://gridly.app`. It retrieves the LP104.5 runtime certificate and then `liberty-48291.addresses.jsonl.gz` below `/data/generated/lp104/txgio-addresses/`.
3. Both artifacts are tracked. The gzip is 2,555,016 bytes and has SHA-256 `792f4f3f76524ef6652fbabf7c1c17d76eb1dfd9d83a71c460c1e038c2841b93`; those values and the exact-only acceptance claims agree with the runtime certificate and adapter identity.
4. The adapter validates certificate identity and policy before fetching the gzip, validates gzip length and digest before decompression, streams gzip JSONL through `DecompressionStream`, and accepts only exact house number, canonical road, locality, ZIP, and FIPS matches. The existing LP102 acceptance gate evaluates the resulting candidate again.
5. Before this patch, `execute` returned any unexpired `gridly_geocode_cache` entry **before invoking the certified adapter**. Therefore a response cached by the pre-LP105.2 general-provider path could skip certificate retrieval, package retrieval, streaming, and exact lookup entirely. If the adapter did execute but returned `package_unavailable`, execution continued into the general provider and later fallbacks. Both paths could expose a misleading substitute after the certified boundary.
6. Business/place traffic, including `Dayton Walmart`, is ineligible for the Liberty adapter and retains the established cache/provider/business pipeline. Road-only traffic is also ineligible for certified address lookup.
7. No site publishing workflow or production value for `GRIDLY_CERTIFIED_ADDRESS_BASE_URL` is checked in. The repository therefore proves the default selected host and expected paths, but not that a deployment publishes the artifacts at that host.

### Verified runtime evidence

The prior checked-in LP105.3 runtime record reports that the deployed browser reached `gridly-geocode`, did not return the certified 276 result, returned a substitute road for the road-only control, and returned a Dayton, Ohio Walmart for the business control. In this execution environment, direct HTTPS probes to both `gridly.app` artifacts and the Supabase function were rejected by the environment's outbound CONNECT proxy with HTTP 403 before reaching either service. Consequently this audit does not claim a new live HTTP observation, a deployed environment-variable value, successful deployed certificate validation, or successful deployed gzip opening.

### Inference boundary

The pre-certification cache ordering and package-unavailable continuation are proven code defects consistent with the recorded symptoms. Repository evidence does **not** prove which defect occurred for any particular production request, nor does it prove that the public artifact host is reachable. Assigning the live failure specifically to DNS, hosting, an environment variable, certificate validation, package retrieval, decompression, or an old cached entry would be speculation without Edge diagnostics or successful production probes.

## Minimal repair

Eligible Liberty requests now invoke the certified provider before reading the general-provider cache. Exact matches and truthful exact misses return immediately. An eligible request whose certificate/package cannot be validated returns a canonical `provider_unavailable` response with bounded diagnostics and HTTP 503; it cannot continue to stale cache, the primary geocoder, registry, or rural fallback. Ineligible road-only, business/place, and non-Liberty requests retain their existing architecture and fallback behavior.

Certificate failure diagnostics now truthfully report `packageAccessed: false` because the gzip was not opened. No matching, package, business-search, provider-boundary, or interpolation policy changed.

## Deployment certification still required

After deploying this Edge source, verify the configured artifact base without exposing secrets, probe the certificate and gzip from an environment that can reach production, and run `await window.gridlyLp1052RuntimeAddressCertification?.()` in the deployed browser. The exact and alias cases must identify the same certified address point; 274 must be a truthful no-result; the road-only case must not surface a substitute; and the Walmart control must remain in the supported geography. A 503 with `certifiedProviderOutcome: "package_unavailable"` is intentionally fail-closed evidence that artifact hosting/configuration still requires operational repair, not permission to invoke fallback.
