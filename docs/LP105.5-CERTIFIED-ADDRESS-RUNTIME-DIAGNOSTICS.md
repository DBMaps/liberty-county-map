# LP105.5 — Certified Address Runtime Diagnostics

## Audit result

### Verified repository facts

1. The browser sends governed searches through `gridly-geocoding-client.js` to `gridly-geocode`; it does not fetch the certificate or gzip package.
2. The Edge Function invokes the Liberty adapter before its general-provider cache and provider pipeline. Eligible adapter failures return `provider_unavailable` without fallback. Ineligible traffic retains the existing cache and provider pipeline.
3. The adapter selects `GRIDLY_CERTIFIED_ADDRESS_BASE_URL`, defaulting to `https://gridly.app`, then requests and validates the Liberty runtime certificate before requesting, validating, and streaming the gzip package.
4. Before LP105.5, diagnostics reported only coarse outcomes and timing. They could not distinguish request eligibility, selected artifact configuration, certificate request/retrieval/validation, package request/retrieval, gzip opening, exact scan, or routing after the adapter.
5. The prior browser helper tested outcomes but discarded the Edge Function's certified-provider diagnostics in the browser client, so its output could not locate the exit stage.

### Verified runtime evidence

The automated fixture-backed runtime executes certificate retrieval and validation, package retrieval, gzip streaming, and exact lookup. It returns the certified 276 address for all governed County Road aliases and a truthful miss for 274. The tests also verify that a malformed certificate stops before package access and reports `certificate_validated` as its failure stage.

No production HTTP request was made for LP105.5 in this repository environment. Therefore this change supplies no new deployed-runtime evidence and does not claim that the deployed certificate, package, environment configuration, or Edge Function revision is operational.

### Inference boundary

The repository proves that the previous diagnostic surface was insufficient to distinguish the reported deployed failure modes. It does not prove which deployment, configuration, artifact-access, validation, streaming, lookup, or routing condition caused the previously reported browser results. Selecting one of those causes before running the deployed LP105.5 helper would be speculation.

## Minimal instrumentation

The adapter now records a bounded allowlisted stage sequence and boolean operational state. The Edge Function adds certified-provider return, fallback, and final-source state without returning URLs, configuration values, artifact contents, request text, credentials, or exception stacks. The browser client copies only the LP105.5 allowlist and caps stage output at 16 entries.

Both of these console calls run the updated certification through the existing client and Edge boundary:

```js
await window.gridlyLp1052RuntimeAddressCertification?.()
await window.gridlyLp1055RuntimeAddressCertification?.()
```

The top-level fields describe the exact-address case. Every case also reports `lastCompletedStage`, `failureStage`, `responseSource`, `certifiedProviderExecuted`, `certificateValidated`, `packageOpened`, `exactLookupExecuted`, `fallbackExecuted`, and `completedStages`. Road-only and business controls remain ineligible and retain existing provider behavior; their diagnostics make that fallthrough explicit.
