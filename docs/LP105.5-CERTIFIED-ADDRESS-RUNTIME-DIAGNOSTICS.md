# LP105.5 — Certified Address Runtime Diagnostics

## Verified root cause and runtime evidence

The deployed diagnostic evidence reported `certifiedProviderExecuted = true`, `failureStage = runtime_certificate_requested`, `certificateFetchReason = network_failure`, `certificateHttpStatus = null`, `packageOpened = false`, and `exactLookupExecuted = false`. The deployed secret set did not contain `GRIDLY_CERTIFIED_ADDRESS_BASE_URL`, so the prior Edge revision selected its `https://gridly.app` default. Denise does not own that host and has no public production domain. The external artifact dependency, not the certified package or LP102 acceptance rules, was therefore the verified failure.

The private Supabase Storage bucket `certified-addresses` now contains the owner-verified objects:

* `lp104/txgio-addresses/liberty-48291.runtime-certificate.json` (uploaded object: 480 bytes)
* `lp104/txgio-addresses/liberty-48291.addresses.jsonl.gz` (2,555,016 bytes)

## Verified repository implementation

The governed path is now browser → `gridly-geocode` → private Supabase Storage → certificate validation → package byte/SHA-256 validation → gzip stream → exact lookup. The Edge Function creates its Supabase client with the server-only service-role environment already used by the function and passes only its Storage client to the reusable county-artifact downloader. The browser receives no authorization header, service-role key, signed URL, object contents, response body, exception, or stack.

`GRIDLY_CERTIFIED_ADDRESS_BUCKET` selects a bounded bucket identifier and defaults to `certified-addresses`. The reusable helper accepts a bucket and bounded object path; Liberty supplies the two governed paths above. It calls the private `download` API directly and never creates a public or signed URL. `GRIDLY_CERTIFIED_ADDRESS_BASE_URL` and `https://gridly.app` are not part of an eligible certified request.

Certificate identity, exact house number, canonical road agreement, county/locality conflict rejection, package size, SHA-256, gzip streaming, exact match, truthful miss, and fail-closed behavior remain unchanged. A missing bucket/object, authorization error, Storage/server/network error, timeout, malformed certificate, identity mismatch, package integrity mismatch, or gzip/scan error returns the certified `provider_unavailable` boundary. Eligible traffic cannot continue into cache or a general provider. Business, curated, road-only, and non-Liberty traffic remain outside this certified provider.

Diagnostics contain only bounded stage names, `storageBucket`, `certificateObjectPath`, `packageObjectPath`, `storageStatusCategory`, booleans, and bounded reasons. Successful evidence includes `storage_bucket_selected`, certificate requested/retrieved/validated, package requested/retrieved/integrity validated, gzip opened, exact lookup executed, exact match or truthful miss, and final response source.

## Deployment (PowerShell 5.1)

From the repository root, deploy the committed Edge Function to the existing project:

```powershell
$ProjectRef = 'nhwhkbkludzkuyxmkkcj'; npx supabase functions deploy gridly-geocode --no-verify-jwt --project-ref $ProjectRef
```

The bucket default requires no new secret. To pin the already-created private bucket explicitly:

```powershell
npx supabase secrets set GRIDLY_CERTIFIED_ADDRESS_BUCKET=certified-addresses --project-ref nhwhkbkludzkuyxmkkcj
```

Do not set `GRIDLY_CERTIFIED_ADDRESS_BASE_URL`; it is obsolete for this certified Storage runtime. Do not make the bucket public. Confirm the deployed function retains `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY`; these platform/server secrets must never be copied into browser configuration or command output.
