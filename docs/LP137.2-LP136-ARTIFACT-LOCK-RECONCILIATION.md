## Cause determination

Hashing the exact object with `git cat-file blob` produces `6223a7b5…`. Hashing those
bytes after LF-to-CRLF conversion reproduces `89cb1a46…` exactly. Therefore the mismatch
was line-ending normalization in a working-tree-derived expectation: it was not historical
artifact replacement, stale committed evidence, or incorrect hash display. The committed
blob and current LF working tree agree, while `.gitattributes` now requires LF for this file.
