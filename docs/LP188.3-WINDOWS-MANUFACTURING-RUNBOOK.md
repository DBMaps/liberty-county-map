# LP188.3 governed community-package manufacturing

The repository-controlled manufacturer consumes the four certified LP188.2A
JSON files without invoking GIS software. It joins canonical PLACE GEOIDs to
the authoritative membership rows, uses the approved LP188.3A identity helper,
preserves existing legacy `communities` strings additively, validates two
isolated byte-identical generations, and promotes only after every gate passes.

The governed output is intentionally outside the runtime package tree at:

`C:\GitHub\Gridly-Source-Data\Processing\Community-Packages\statewide-identity-v1`

It contains `counties\<county-fips>.json` and
`lp1883-community-package-certification.json`. Nothing registers, deploys, or
activates these artifacts, and current operational manifests are read-only.

From Windows PowerShell, with the application repository checked out at the
default location, run:

```powershell
Set-Location C:\GitHub\liberty-county-map
npm run test:lp1883
& .\Gridly-Source-Data\Tools\Build-Scripts\Build-LP1883CommunityPackages.ps1 `
  -InputDirectory 'C:\GitHub\Gridly-Source-Data\Processing\Census-Places' `
  -RepositoryRoot 'C:\GitHub\liberty-county-map' `
  -OutputDirectory 'C:\GitHub\Gridly-Source-Data\Processing\Community-Packages\statewide-identity-v1'
Get-Content 'C:\GitHub\Gridly-Source-Data\Processing\Community-Packages\statewide-identity-v1\lp1883-community-package-certification.json' -Raw
```

Do not treat the build as operational activation. Review the returned governed
certification and all output hashes before considering LP188.3 complete.
