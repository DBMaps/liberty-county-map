# LP201.1 — governed OSM named-place evidence pipeline

## Architecture and frozen inputs

LP201.1 reuses the owner-manufacturing pattern in `Build-CensusPlaceCountyMemberships.ps1`: strict source locks, QGIS/GDAL bootstrap through `gridly-gis-env.ps1`, read-only OGR extraction, temporary staging, stable sorting, review buckets, and fail-closed promotion. It also follows V684's offline OSM extraction → deterministic inventory → explicit review bucket → later governance boundary. Unlike V684, identity reconciliation is against Census PLACE GEOIDs rather than a roadway corridor.

The canonical identity input is `data/generated/gridly-statewide-consumer-community-projection-v1.json` (1,859 eligible Census PLACE identities, governed type, and county memberships). Canonical polygon geometry is read-only 2025 TIGER/Line Texas PLACE geometry. LP199 and LP200 reports remain optional comparison evidence, never identity authority. The OSM lock is exactly `texas-260625.osm.pbf`, 707,715,853 bytes, SHA-256 `1d80efe1b19b075d036363d722366870df3efb7fbd4a45dc9f16797868ff4413`.

## Owner command

Run from the owner Windows/QGIS environment after setting `OSM_CONFIG_FILE` to the QGIS `osmconf.ini`:

```powershell
Gridly-Source-Data\Tools\Build-Scripts\Build-LP2011OsmNamedPlaces.ps1 -Mode WhatIf
Gridly-Source-Data\Tools\Build-Scripts\Build-LP2011OsmNamedPlaces.ps1 -Mode Apply
Gridly-Source-Data\Tools\Build-Scripts\Build-LP2011OsmNamedPlaces.ps1 -Mode Verify
```

`WhatIf` performs the real preflight, extraction, and reconciliation without governed writes. `Apply` writes only `reports/lp2011` evidence. `Verify` recomputes and byte-compares every artifact. No mode modifies runtime files.

The focused comparison cohort is loaded from the actual LP197 governed camera registry (Austin, Dallas, El Paso, and Fort Worth), not reconstructed from memory. Its LP199 geometry-centroid evidence is joined by GEOID. LP200 is reported as null when the preserved owner candidate artifact is unavailable; values are never inferred. Dayton, Tyler, Waco, and Corpus Christi enter statewide reconciliation normally, but are not mislabeled as LP197 reference cameras when the governed LP197 artifact does not contain them.

## Rules and taxonomy

Names are normalized exact evidence only; they never establish identity without polygon containment. Eligible automatic OSM classes are `city`, `town`, `village`, and `hamlet`. Suburb, neighbourhood, locality, and all other values remain classification concerns. The buckets are A high-confidence unique, B multiple candidates, C duplicate-name geographically disambiguated, D in-polygon name mismatch, E no candidate, F unmatched OSM candidate, G classification concern, and H hard conflict/invalid. Statewide duplicate names are resolved only when exactly one exact-name candidate is inside the governed canonical polygon.

## Environment status

The repository clone intentionally does not contain the 707 MB owner PBF, QGIS GDAL, `osmconf.ini`, or statewide TIGER PLACE shapefile. Consequently no statewide results are fabricated or committed from this container. The owner command fails closed until those exact inputs are available. This is an environment limitation, not a runtime dependency and not permission to download replacements.

## Runtime boundary

All outputs are evidence-only. There is **no runtime activation**; `js/app.js`, community/package registries, startup/reload persistence, resolver behavior, and camera selection are untouched.
