## Atomic load and rejection policy

The policy is **verify then no-op if identical**. The SQL begins one transaction and takes `SHARE ROW EXCLUSIVE` on only the county table, serializing concurrent writers while allowing ordinary reads. A transaction-local staging table receives all 254 source rows. Preflight checks target columns, RLS, index, and trigger state. An empty target is filled in two 127-row batches. A nonempty target is accepted only when it has exactly 254 rows and every FIPS, version, and geometry matches; this branch performs no target INSERT or UPDATE. Every other nonempty state raises an exception and rolls back. After load it checks 254 rows, exact FIPS correspondence, type, SRID, validity, point count, and equivalence before commit. Temporary tables disappear on commit or rollback. The script creates no lasting helper, grant, policy, or schema object.

Disposable PostgreSQL 17/PostGIS 3.6.2 tests cover an empty load, exact replay with unchanged `xmin`, one-row and 253-row states, changed geometry, wrong-county geometry at 254 rows, duplicate-key collision, extra valid-format out-of-scope FIPS, and a forced failure after 127 inserts. The strict boundary check uses Liberty (`48291`) and Chambers (`48071`): interior accepted by `ST_Contains`; exact/shared boundary touches but is not contained; neighboring interior is not contained. The GiST plan check explicitly addresses the PostGIS operator schema. No inclusive `ST_Covers` rule is substituted for responder authority.

## Compatibility, performance, and remaining production gates

The local fixture uses PostgreSQL 17.10 and PostGIS 3.6.2; Phase 12 production evidence records PostgreSQL 17.6/PostGIS 3.3.7. The loader uses the PostGIS geometry type and `ST_GeomFromGeoJSON`, `ST_SetSRID`, `ST_Multi`, `ST_IsValid`, `ST_SRID`, `ST_GeometryType`, `ST_NPoints`, `ST_Equals`, and `ST_AsBinary`. Certification additionally uses `ST_Extent`, `ST_Contains`, `ST_Touches`, `ST_Intersection`, `ST_Boundary`, `ST_PointOnSurface`, `ST_GeometryN`, `ST_ExteriorRing`, `ST_PointN`, and `ST_MakeEnvelope`; drift fixtures use `ST_Translate`. These are conservative, long-standing APIs rather than newer PostGIS-only features, but identical behavior on deployed 3.3.7 has not been exercised locally and must be proven by separately authorized production postload verification. Local time and index-plan evidence are recorded in the certification JSON; they are not a production latency guarantee.

An uncommitted transaction can simply roll back. After commit, do not issue an automatic DELETE: first prove whether any dependent consumer or responder authority has used the rows. A separately authorized rollback could restore the accepted prepopulation checkpoint if no dependent use exists; otherwise preserve history and use an approved forward fix. The one-table lock blocks competing writes briefly but allows existing readers to see a consistent pre- or post-commit state; no downtime promise is inferred. A production owner must confirm maintenance/coordination, backup/recovery state, migration inventory, reporting and publishing controls, and absence of authority dependency before execution.
