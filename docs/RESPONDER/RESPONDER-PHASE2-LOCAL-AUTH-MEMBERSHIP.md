# Responder Phase 2 local Auth and membership fixture

Implementation version: `responder.agency.v1.phase2.1`. It builds on the frozen Phase 0 contract and the committed Phase 1 local schema. [Apply SQL](../../db/responder-local/002_phase2_auth_membership_apply.sql), [fixture tests](../../tests/responder-phase2-local-auth.test.mjs), and the [54-vector map](../../reports/responder/responder-phase2-vector-map.json) are **local/disposable only**. There is no Supabase project connection, real Auth user, SMTP message, dashboard, production RPC/RLS, consumer output, or publishing.

## Synthetic identity and future Auth mapping

`agency_private.local_auth_identities` holds fixture UUIDs shaped like future `auth.users.id`, normalized email, `RESPONDER` or separate `GRIDLY_ADMIN` identity class, `aal1`/`aal2`, session-active flag, eligibility, and a monotonic session epoch. It contains no password, TOTP secret, real session, invite token, or production subject. Phase 2 command helpers accept an actor UUID **only from the trusted local test harness** and are not executable by `responder_app_fixture` or PUBLIC. A future server implementation must replace that parameter with server-derived `auth.uid()` and use current server assurance, not a client-supplied claim. The local helper is not a deployable authentication boundary.

Every dashboard/membership authorization reads the live fixture identity and membership rows. Unknown identities, inactive sessions, ineligible identities, and `aal1` fail before privileged transitions. `aal2` represents the future TOTP assurance requirement; it does not enroll or verify TOTP. A suspended/revoked member's local session is marked inactive and their session epoch increments. Later requests check the live DB state even if a stale token still advertises an old role. Actual Supabase session revocation and JWT refresh are deferred.

## Membership, roles, and invite lifecycle

An invite creates both a digest-only `organization_invites` row and an `invited` membership. Matching email/identity, digest, unexpired created state, active verified organization, one-active-org rule, and actor `aal2` are required to redeem. Redemption atomically marks the invite redeemed, activates membership, and appends invite-redemption and activation events. Exact reuse returns bounded `already_processed` without a new event; wrong identity/digest, revoked invite, and expiry fail closed. The seven-day expiry is a **provisional local fixture value**, not live policy. No email is sent.

Agency Admins may invite, change a current member's role, suspend, revoke, reinstate, or revoke an invite only within their verified active organization. Allowed membership roles remain exactly VIEWER, RESPONDER, SUPERVISOR, AGENCY_ADMIN. GRIDLY_ADMIN is never an agency membership. Self-promotion, invalid roles, cross-org administration, and leaving zero active Agency Admins through demotion/suspension/revocation are denied. Suspension blocks privileged actions and invalidates the local session. Reviewed reinstatement requires the target to establish a new active `aal2` fixture session; revocation is terminal for that membership row.

The Phase 1 schema used an all-history unique `(organization_id,user_id)` constraint. That prevented the frozen Phase 0 rule that a **revoked membership stays terminal and return requires a new invitation and membership record**. Phase 2 replaces it locally with a unique index over *current* (`invited`,`active`,`suspended`) memberships and preserves Phase 1's independent unique index on `user_id WHERE status='active'`. Revoked history remains in place. No Phase 0 contract was changed.

## Gridly recovery, audit, and command surface

`recover_admin` is a separate GRIDLY_ADMIN fixture path. It requires active `aal2` Gridly identity, a nonempty reason, explicit reviewed flag, verified organization, no active Agency Admin, and an eligible target other than the Gridly actor. It either restores a suspended existing Agency Admin after fresh `aal2`, or creates a new AGENCY_ADMIN invitation and membership while leaving a revoked prior row untouched. An ordinary active admin, self-recovery, missing review, or absent assurance fails closed. The reviewed flag is fixture evidence only; future governance must verify independent agency contact through a separate owner-approved process.

The local `phase2_membership_command` returns only bounded Phase 0-style codes such as `accepted`, `already_processed`, `invalid_request`, `forbidden`, `suspended`, and `expired`. It is a trusted fixture helper, not a production RPC or Phase 5 operation-receipt protocol. Membership and invite mutations plus append-only `organization_governance_events` are in one SQL function transaction. Events record org, actor, affected membership, before/after bounded state, reason, correlation UUID, and server timestamp. They contain no raw invite token or credentials. Denials leave no business event. Existing Phase 1 append-only guards reject update/delete/truncate.

The local `phase2_dashboard_access` and `phase2_membership_access` functions return bounded authorization decisions only. They render no UI, perform no publishing, and expose no private data to consumers. The agency publishing gate remains false and independent from community `reporting_enabled`. County authority, responder update commands, RLS, dashboard rendering, and consumer projection remain deferred.

## Disposable test scope

The Phase 2 harness requires explicit localhost port/user and the exact server data directory under Temp with a `gridly-responder-phase2-*` name. It verifies PostgreSQL 17.10 and PostGIS 3.6.2, creates a unique database, applies Phase 1 and Phase 2 local SQL, runs synthetic UUID/digest scenarios, and drops the Phase 1 schema/fixture roles and database in registered teardown. [Phase 1 regression tests](../../tests/responder-phase1-local-schema.test.mjs) remain separate and unchanged. No direct client write grant is introduced.
