# Responder Phase 5: disposable local agency-update commands

This is a PostgreSQL 17.10/PostGIS 3.6.2 **local fixture**, outside production migrations. It does not use Supabase Auth, deploy RPCs, publish agency content, implement a dashboard, or create a consumer projection. The independent `agency_publishing_enabled` seed remains `false`. The only positive activation tests temporarily enable that gate in a dedicated synthetic test database and restore `false` immediately.

## Frozen command boundary

`db/responder-local/005_phase5_local_command_apply.sql` installs one `SECURITY DEFINER` entry point, `agency_private.phase5_agency_update_command(jsonb)`. It accepts the frozen `contract_version`, canonical UUIDv4 `operation_token`, `action`, `organization_id`, action-specific `payload`, and, for existing updates, `update_id` plus `expected_revision`. The server derives the actor solely from the Phase 4 PostgreSQL login binding; payload and custom GUCs cannot choose an actor. Allowed actions are `create_draft`, `edit_own_draft`, `edit_another_draft`, `submit_for_review`, `return_for_changes`, `activate_non_closure`, `activate_road_closed`, `edit_active_update`, `renew_update`, `resolve_update`, and `withdraw_update`.

The frozen update lifecycle is `draft → pending_review → active`, with `pending_review → draft` for reviewer return, then `active → resolved/withdrawn` or unpublished `draft/pending_review → withdrawn`. There is **no** separate approval command, approved update state, or approved update event. `activate_non_closure` is the Supervisor/Admin review decision for four non-road conditions; the frozen matrix does not impose a second-actor check there. `activate_road_closed` additionally compares the immutable author Auth ID with the current activator ID, including when the author is a Supervisor/Admin. `GRIDLY_ADMIN` has no ordinary agency-command grant.

## Input, results, and replay

Create/edit payloads supply one WGS84 longitude/latitude point, one of the five frozen condition types, bounded title/impact/detail and optional road labels. Edits are full field replacements. Unknown keys, client source-family fields, HTML-like markup, invalid/oversized content, malformed IDs/revisions/tokens, nonfinite/out-of-range coordinates, and invalid expiry bounds return `invalid_request`. Source family is server-fixed to `AGENCY_OFFICIAL`. A draft may hold a crossing ID, but activation fails closed while the private fixture has no governed crossing resolver; no unvalidated crossing reference may become active. Rate policy is not invented from the provisional pilot cap.

Only frozen statuses can leave the command: `accepted`, `pending_review`, `already_processed`, `invalid_request`, `forbidden`, `out_of_scope`, `stale_revision`, `suspended`, `expired`, `rate_limited`, `maintenance`, `retryable_failure`. Denials return only a status. Accepted results carry update ID, revision, and an opaque correlation UUID. No raw SQL error, token digest, or employee details are returned. Unknown SQL exceptions map to `retryable_failure`, with SQLSTATE/message retained only in the disposable server log for local diagnosis.

The token digest is SHA-256 of the canonical 16 UUID bytes. A canonical JSONB request without the token is separately hashed for payload identity. An advisory transaction lock serializes same-token attempts; `agency_operation_receipts` binds digest, actor, organization, command, target, payload digest, bounded result, and acceptance time. Exact replay returns `already_processed` with the stored correlation ID; changed payload/actor/org/action/target returns `invalid_request`. Rejected commands leave no receipt, update mutation, or business event. Phase 1 append-only triggers reject receipt UPDATE/DELETE/TRUNCATE. The community-report replay domain is untouched.

## Live authorization and revision

Every command checks active eligible `aal2` identity, live membership and role, and verified active organization. Suspended membership/organization returns `suspended`; revoked/inactive/unverified/cross-org and hidden targets return `forbidden`. Draft/create/edit/submit/return/activate/active-edit/renew call the Phase 3 server-side county point check. It resolves the county from the candidate/stored point, rejects exact boundaries and outside/ambiguous points, requires a current approved full polygon, and treats supplied FIPS/authority ID/version as comparison claims only. Resolve and withdraw remain available while the gate is off, as frozen.

Existing-target commands lock the row and compare `expected_revision` before updating it exactly once. Two concurrent edits at the same revision yield one accepted and one `stale_revision`. Every accepted mutation appends exactly one frozen event at that revision: `update_draft_created`, `update_draft_edited`, `update_submitted`, `update_returned`, `update_activated`, `road_closure_activated`, `update_edited`, `update_renewed`, `update_resolved`, or `update_withdrawn`. The road activation event privately records the distinct immutable author ID and activator ID; no token is logged. Denials and replays add no business event.

## Gate and expiry

Activation and active edit/renew require the independent gate to be true. The normal false seed returns `maintenance`. Accepted activation sets status, current authority, `activated_at`, `expires_at`, revision, and event. Expiry defaults to 12 hours; explicit duration cannot exceed 24 hours from server time. Phase 5 updates Phase 1's initial-only expiry constraint to a rolling server-updated 24-hour window for explicit reviewed renewal. `phase5_effective_status` derives `expired` at `as_of >= expires_at`; stored status remains `active` for history, but an effectively expired update cannot be edited, renewed, resolved, withdrawn, or reactivated. No Cron is used.

The function has a fixed `pg_catalog` search path, schema-qualified private reads/writes, no caller-controlled SQL or role escalation, and EXECUTE granted only to the Phase 4 agency fixture group. A separate non-login, non-superuser definer receives only the table/function grants used by this command and `BYPASSRLS` to read the forced local policies; no login inherits that definer role. Ordinary roles retain no direct-write grants or policies. The synthetic login binding and local RLS bypass are **not** a production Auth/RLS pattern; any production design needs separate owner review and server-verified `auth.uid()`/AAL binding.

## Certification boundary

`tests/responder-phase5-local-command.test.mjs` creates a unique localhost database in a verified disposable `gridly-responder-phase5-*` Temp cluster, loads the certified 254-county source, and tests synthetic organizations/actors, commands, replay, gate restoration, expiry, concurrent revisions, append-only evidence, and direct-write denial. `tools/responder-local/run-phase5-regressions.ps1` runs existing Phases 1–4 suites in separate disposable localhost clusters. `reports/responder/responder-phase5-vector-map.json` records 54 frozen vectors: 9 previously complete, 33 newly complete, 2 dashboard-deferred, 4 consumer-deferred, and 6 backend-deferred with reasons. The local gate is false at the end of the Phase 5 suite. Production migration, Auth/RLS design, dashboard, consumer projection, deployment, and live publication remain deferred.
