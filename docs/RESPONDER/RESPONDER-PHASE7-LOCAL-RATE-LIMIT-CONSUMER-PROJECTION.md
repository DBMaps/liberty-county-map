# Phase 7 local publication rate and consumer projection

Phase 7 is a disposable PostgreSQL 17.10/PostGIS 3.6.2 fixture. Apply `db/responder-local/007_phase7_local_rate_consumer_apply.sql` after Phases 1–6. It is not a production RPC, consumer deployment, or authorization to enable agency publishing. `agency_publishing_enabled` remains seeded false.

## Owner-approved publication rate

The owner approved at most **60 successful agency activations per organization in a rolling 60-minute window**. Both `activate_non_closure` and `activate_road_closed` use the Phase 7 wrapper. The window counts successful activation rows with an activation event and server-held `activated_at > command_time - interval '60 minutes' AND activated_at <= command_time`. Thus 59m59s counts; exactly 60m and older do not. Draft, edit, submit, return, failed or rate-limited activation, resolve, withdraw, verification, and authority governance do not consume capacity. Resolved and withdrawn posts that were successfully activated still count until their activation ages out. The result at capacity is only `rate_limited`; no internal traffic count is returned.

The wrapper takes an organization row `FOR UPDATE` lock before delegating an activation to the fully validated Phase 5 command. That lock serializes concurrent attempts across actors in the same organization. After a successful Phase 5 activation, the wrapper counts the inclusive candidate. If it would be number 61, it raises a local exception inside a PL/pgSQL subtransaction; the update, lifecycle event, and Phase 5 receipt all roll back, then the wrapper returns `rate_limited`. Exact accepted-token replay delegates to Phase 5 and returns `already_processed` without consuming another slot. A denied activation has no accepted receipt under the frozen replay contract, so immediate retry while full stays `rate_limited`, and retry may succeed after capacity returns. Resolve and withdraw continue through Phase 5 even with the gate off and quota full. Direct agency execution of the Phase 5 entry point is revoked in the Phase 7 fixture; ordinary agency roles receive only the wrapper.

## Public projection and owner contract repair

The owner clarified the frozen consumer eligibility text in `RESPONDER-V1-CONSUMER-PROJECTION.md`. An original `pending_review → active` event establishes publication authority. The latest update revision must have exactly one matching active lifecycle event: its activation event, `update_edited`, or `update_renewed`. Edit and renewal do not create another activation event. Missing, mismatched, or duplicate event lineage fails closed; the `(update_id,revision)` uniqueness constraint remains. Phase 7 captures the organization operation epoch in the update at first activation. The public read checks that epoch against the current organization epoch, preventing old posts from appearing after suspension and reinstatement.

The local `responder_public.agency_updates` view emits one JSON document per eligible update. Each document has exactly the frozen 18 keys: `update_id`, `organization_public_name`, `approved_department_name`, `verified_agency`, `verified_agency_label`, `condition_type`, `impact_level`, `title`, `detail`, `location`, `road_name`, `cross_street`, `crossing_id`, `source_family`, `activated_at`, `updated_at`, `expires_at`, and `display_lifecycle_state`. No approved department source exists in the local schema, so `approved_department_name` is null, never inferred. `location` contains only latitude and longitude derived from the stored point. `verified_agency=true`, `verified_agency_label="Verified Agency"`, `source_family="AGENCY_OFFICIAL"`, and lifecycle display `active` are fixed for returned rows. The “Agency update” presentation wording is derived from the agency source identity; it is not an extra projected key. Employee, membership, audit, review, receipt, and authority provenance fields never enter the document.

Eligibility is rechecked against live server state on each read: gate true; verified active organization; stored active update with activation and effective unexpired time; matching operation epoch; current approved non-revoked county authority effective at read time and containing the point; allowed condition/content; no unresolved crossing reference; valid original activation event (including distinct author and approver for `road_closed`); and valid current-revision event matching current authority. Stored draft, pending, resolved, withdrawn, effectively expired, suspended-organization, or stale-authority rows return no public document. Expiry uses server time directly, so no Cron or cleanup job is needed. Suspension and authority revocation withdraw affected active posts transactionally in Phase 6; the projection hides them immediately, and reinstatement does not republish them.

The synthetic public reader has `SELECT` only on the public view and cannot read the private responder schema or execute agency/governance commands. The view calls a server-time-only entry point. A separate private time-parameterized function exists for deterministic expiry testing; it is not executable by the public reader. The public view owner is a non-login read-only definer. No raw private authority geometry, employee identity, or evidence is granted to the public role. `AGENCY_OFFICIAL` remains separate from community, DriveTexas, NWS, crossings, and other source families; no cross-source table is rewritten.

The local rate index on `(organization_id,activated_at)` supports the rolling count. Existing organization/status/expiry, authority date/geometry, and event update/revision indexes support projection eligibility. `source_family` is constrained to one value in the private agency table, so a separate source index has no selectivity in this local fixture. The Phase 7 suite checks these indexes, runs a bounded `EXPLAIN ANALYZE` on the synthetic projection, and verifies current-state privacy and exact 18-key output.

## Frozen vectors and boundary

Phase 7 newly completes N24, N27, N34, P17, P18, and P19: six full vectors. Of 54 total, 45 were complete before Phase 7 and 51 are now complete. P01 and P20 remain dashboard-deferred. N26 remains backend-deferred because an ordinary agency login receives SQL permission denial rather than the frozen bounded `forbidden` result from a governance command; granting governance execution to agency roles would weaken the role boundary. No consumer vectors remain deferred.

Only synthetic data in a disposable localhost cluster is used. A positive projection fixture briefly sets the local gate true and restores it to false before teardown. Production deployment is explicitly deferred. This phase does not access Supabase, production Auth, live email, consumer services, dashboards, or real agency data, and does not publish anything live.
