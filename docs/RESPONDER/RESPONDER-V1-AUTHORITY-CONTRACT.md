# Responder / Agency V1 county authority contract

Contract version: `responder.agency.v1.phase0.1`. V1 is **county-first**. The [county-authority manifest](../../reports/responder/responder-v1-county-authority-manifest.json) records the current proposed geometry source, its canonical tracked-byte SHA-256, schema ID, all 254 FIPS codes, and structural checks. It is evidence for a future local fixture, **not** permission to activate that geometry for agency publishing.

## Version identity and source governance

An authority version has a server UUID, organization UUID, five-digit county FIPS, `COUNTY` scope type, immutable polygon, source path and SHA-256, source schema/package version, approval actor/time, effective interval, and explicit revocation. The server records the exact authority version on every update activation/revision. Client-supplied version IDs are only selectors to verify against current server authority; they never create or broaden scope.

The proposed source is `assets/location-resolution/gridly-authoritative-texas-county-geometry-v1.json`. Its canonical **Git blob** has 13,934,264 bytes and SHA-256 `6c6eeb549bb5e03d79efbc4d421783c06988c81c0f728c79add32f8c219e3d49`, matching the existing repository manifest. On this Windows checkout, Git converts its single terminal LF to CRLF, yielding a one-byte-longer working copy and a different incidental checkout hash. Future fixture loaders must use canonical tracked bytes or explicitly normalize this line ending before comparing authority identity; they must not bless a mismatched geometry silently. The existing manifest says `activateRuntimeAuthorized=false`, `deployAuthorized=false`, `activationPerformed=false`, and `deploymentPerformed=false`. Phase 3 needs a separate owner approval for agency authority use.

The artifact has 254 distinct, ascending Texas county FIPS values from `48001` to `48507`, 254 nonempty unique county IDs, and a `Polygon` for every county. All 254 exterior rings are closed; coordinate tuples are finite longitude/latitude values in range. Its `generatedAt` is the deterministic epoch value `1970-01-01T00:00:00.000Z`. The file has no explicit CRS declaration, so **EPSG:4326 longitude/latitude is a documented assumption requiring local geometric certification**, not a claim proven by this metadata alone.

## Server decision

At create/submit/activate/edit/renew, resolve the acting organization and its current approved county authority from private server state. Require verified active organization, active member with correct role and `aal2`, current effective and non-revoked authority version, matching FIPS, valid complete polygon, and a finite point strictly inside the polygon (including hole handling). A point exactly on a shared boundary or an otherwise ambiguous edge fails closed for manual correction. Do not grow the polygon with an arbitrary buffer or treat proximity to a border as authorization. The server repeats the check at every publication-changing operation and at consumer read time.

Unknown/null FIPS, missing/invalid geometry, stale source hash or authority version, revoked/expired authority, point outside county, suspended organization, or spoofed client authority ID returns a bounded denial with **zero business write**. Authority revocation atomically withdraws affected active posts and records events; organization suspension does the same. Reinstatement never automatically republishes them. The public projection checks the current scope again and is empty for ineligible rows.

County authority does not imply municipality, fire/EMS district, special district, roadway segment, mutual aid, or statewide authority. Before any of those exist, future phases must govern a full polygon/roadway source, provenance/hash, overlap and shared-edge rules, independent approval version, spatial and negative fixtures, and owner authorization. [PLACE presentation points](../../data/generated/gridly-statewide-place-presentation-v1.json) and [PLACE county memberships](../../data/generated/gridly-statewide-consumer-community-projection-v1.json) are expressly forbidden substitutes for authority polygons.

For the non-executing vector inventory, `authorityState` is one of `approved`, `not_required`, `revoked`, `stale`, `unknown_fips`, `out_of_scope`, `ambiguous_boundary`, `spoofed_id`, or `missing_geometry`. Only `approved` can grant publication; `not_required` is used solely for non-geographic reads/governance actions. The other values are denial scenarios, not database status names.
