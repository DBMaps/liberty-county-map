# Responder / Agency V1 command, status, and replay contract

Contract version: `responder.agency.v1.phase0.1`. This is a **logical** protocol; it does not define executable RPC signatures or SQL. Canonical actions are listed in the [role matrix](RESPONDER-V1-ROLE-MATRIX.md). Reads (`read_dashboard`, `read_own_membership`, `read_org_roster`, both audit reads, `read_consumer_projection`) are bounded read surfaces, not mutations. No browser receives a service key or direct write grant.

## Shared envelope and validation

- Mutations carry `contract_version`, `action`, UUIDv4 `operation_token`, `actor` from the authenticated session (never trusted from payload), optional target ID, `expected_revision` for an existing target, and an action-specific object. A create has no expected revision; a target mutation requires one. An invite redemption checks the invite's current single-use state instead of a caller-authored role.
- `aal2` and a live membership are mandatory for agency mutations; Gridly governance additionally requires a separately verified platform role. `request_verification` is the sole unaffiliated `aal1+` exception and grants no agency access. Every decision reads current DB state, not `user_metadata` or stale JWT membership claims.
- Reject unknown keys, nested executable content, HTML/script markup in visible copy, nonfinite coordinates, unknown types/statuses, unapproved source family, and overlong UTF-8 payloads. Update payload <= **8 KiB**; membership <= **2 KiB**; governance <= **4 KiB**. Title <= 120 characters; detail/reason <= 1,000; road/cross-street <= 120 each; crossing ID <= 120; email <= 254. These are contract bounds for later local test fixtures, not a live API.
- An active update defaults to `expires_at = server_now + 12 hours` and may not exceed `server_now + 24 hours`. Renewal must occur before effective expiry and is an explicit reviewed revision. Client time cannot extend the bound. Store one WGS84 point; derive display latitude/longitude from that point.
- Organization, membership, gate, authority version, county point, type, revision, and lifecycle checks occur in one server transaction. Failure rolls back receipt claim, row change, and business event together. Denial telemetry may record a bounded code separately without raw body/token or private row existence.

## Bounded result status vocabulary

Only these codes may leave a command: `accepted`, `pending_review`, `already_processed`, `invalid_request`, `forbidden`, `out_of_scope`, `stale_revision`, `suspended`, `expired`, `rate_limited`, `maintenance`, `retryable_failure`. No raw SQL error, private row presence, Auth metadata, invite token, actor detail, or unredacted original response leaves a denied/replayed command. `forbidden` also covers hidden-target lookup; `maintenance` means the **agency** publishing gate blocks public mutation; `expired` covers invite/update time bounds. Read surfaces return bounded data or `forbidden` without widening this status set.

## Agency-only operation receipt

The caller generates one canonical UUIDv4 token per logical mutation. The server hashes its canonical 16 UUID bytes with SHA-256 and stores only that digest in a **separate agency replay domain**. The receipt binds actor Auth user ID, organization, family/action, target, payload digest, bounded result code/correlation, and acceptance time. A concurrent duplicate waits for the first transaction outcome. Same token + same actor/action/target/payload digest returns `already_processed` with a bounded correlation; same token with any mismatch returns `invalid_request`. A failed authorization or rolled-back mutation leaves no accepted receipt or partial business row. Receipt retention is **provisional**: at least the affected update's replay-risk lifetime, with a proposed three-year class pending owner/legal policy. Never reuse community `report_retention.replay_evidence`, device links, or observation receipts.

## Safety at publication

The server compares immutable draft `created_by_user_id` with authenticated approver `auth.uid()`; equality rejects `activate_road_closed` even if the author is S/A. If the author is suspended, the draft stays hidden and a current S/A may withdraw it; a replacement must be a **new draft by a current actor**, with its own review. If no second approver exists, a closure remains pending and invisible. A Supervisor returns a draft with a reason and a new revision. No UI-side role/geography filter is authorization.
