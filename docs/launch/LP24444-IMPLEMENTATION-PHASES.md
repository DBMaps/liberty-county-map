This is a plan, not authorization to execute the future branches/services/builds now. Contract `LP24444.v1`; [machine dependency graph](../../reports/lp24444-launch-contracts.json) is authoritative. Nine small phases follow LP244.44. Scope expands only through explicit future work, with tests and a reviewable local change per phase. Never bundle native credentials, backend production activation and all consumer changes into one branch.

Every phase preserves Home/report compatibility, portrait behavior, privacy boundaries and existing source governance. Later code must use reviewed feature gates with default-disabled remote delivery until the relevant acceptance gates pass; placeholders must say unavailable rather than simulate live alerts. Rollback must stop delivery safely without destroying unrelated reporting/user data. Production promotion is separate owner-controlled work.

## PHASE-01 — Dependency refinements

LP244.52 does not postpone consent or quiet hours until after delivery. Backend eligibility predicates are in .48, user controls/native status in .49, Home delivery in .50; .52 is full integration/accessibility certification. Similarly outage handling accompanies each source adapter, while .52 tests cross-source behavior. Complete winter normalization is .46, not a post-launch picker change. Typed target resolution is before any Home send. Foreground Around Me is .47, and no later phase silently adds background current-area subscriptions.

LP244.48 may be developed after .46 independently of .47, but .49 joins both. Native SDK/owner provisioning preparation can occur during future implementation planning without changing this dependency graph; enabling production delivery still waits. Keep platform-specific commits/candidates reviewable within .49; if actual scope exceeds a certifiable branch, split into numbered subphases preserving the same acceptance boundary. No unrequested subagents/parallel branches are created by this plan.

Each future phase must record before/after capability, changed files, focused tests and known failures, runtime/native/backend boundaries, data compatibility and rollback. External credentials/provider selection are supplied through approved operational processes, never committed. Legacy LP165 manifest drift is investigated independently before treating that old report as current certification. Local passing fixtures do not replace Mac provisioning/physical iPhone or Android runtime gates.
