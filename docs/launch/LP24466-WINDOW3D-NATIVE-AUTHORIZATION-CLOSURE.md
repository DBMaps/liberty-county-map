## Challenge, limiter, binding and replay

The Edge challenge entrypoint `gridly-subscription-challenge` is POST-only, accepts a bounded `{platform}` body, and returns a random 256-bit challenge, two-minute expiry and fixed protocol version. The private issue RPC stores only its SHA-256 hash with platform/purpose, performs bounded cleanup, caps issuance at 300/minute and live challenges at 10,000. The verifier recomputes the same canonical binding as the native client and atomically consumes the challenge before store/provider verification. Apple counter regression and Google challenge reuse deny. The migration has no account, purchase, raw challenge, install ID or email field.

Supabase Edge does not expose a source signal here that this implementation can independently authenticate. The proposed **Cloudflare gateway** is therefore the trusted source limiter: on the public `gridlygo.com/subscription-challenge` route, Cloudflare's `CF-Connecting-IP` connection header keys a Rate Limiting binding at 10 requests/60 seconds. The Worker ignores caller-controlled `X-Forwarded-For`, sends only platform to the Edge challenge endpoint, and adds a separate 64-hex gateway token stored in Cloudflare and Supabase secret stores. Direct Edge calls without that token fail. Missing Cloudflare connection metadata or binding fails closed. The binding's 60-second window bounds limiter state; the database RPC adds the global cap. Shared mobile carrier IPs could hit the per-IP cap, so real cohort behavior needs review. A Wrangler 4.141.0 **dry-run bundle passed** with the rate binding. The Worker route, binding, token and Edge endpoint are **not deployed**; the exact Cloudflare source-header assumption must be checked in its deployed route. [Cloudflare Rate Limiting binding and IP caveat](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/).

The fixed binding array includes protocol, challenge, platform, environment, product, Google base plan, nonce, continuity binding and SHA-256 of bounded store evidence. The same SHA-256 digest is passed to App Attest and base64url encoded as Google's `requestHash`. Field order and value-mutation tests pass. `gridly-native-edge-transport.mjs` fixes the Cloudflare challenge URL and Supabase verifier URLs, uses only the existing public publishable routing key for verifier calls, and refuses nonnative or wrong-platform calls. The browser has no native attestation bridge.
