## 4. Encryption / rotation

AES-256-GCM, 128-bit tag, fresh random 96-bit IV, ciphertext base64url; AAD `gridly-google-ack-v2\0<environment>\0<chain_fingerprint>\0<key_version>`. The HMAC fingerprint uses a distinct server key. Work row stores **nonsecret key_version**, IV and ciphertext, never key/raw token. The server imports current/optional previous key as nonextractable CryptoKeys. New writes use CURRENT only. Open selects ONLY exact current or configured previous identifier; no dynamic DB key lookup. Previous key requires absolute `retireAt` in future but <=one hour at composition; it is checked on EVERY decrypt. Unknown/missing/retired version fails closed with safe `key_version_unavailable`, terminal deletes the row and increments bounded health. Wrong tag/tamper/malformed ciphertext safely yields `cipher_invalid`, terminal deletes. Missing CURRENT key closes Google verifier/operations; independent SQL housekeeping remains functional. Rotation procedure: provision CURRENT+PREVIOUS with explicit retirement, move new writes to CURRENT, observe count-only prior-version work to zero, then remove PREVIOUS before retirement. Never blindly rotate with pending rows. Production key values were not generated, printed or committed.

Exact future server secret **names only**: `GRIDLY_GOOGLE_ACK_AES_CURRENT_VERSION`, `GRIDLY_GOOGLE_ACK_AES_CURRENT_KEY_B64`, optional jointly configured `GRIDLY_GOOGLE_ACK_AES_PREVIOUS_VERSION`, `GRIDLY_GOOGLE_ACK_AES_PREVIOUS_KEY_B64`, `GRIDLY_GOOGLE_ACK_AES_PREVIOUS_RETIRE_AT`; unchanged privileged dependencies `GRIDLY_ENTITLEMENT_FINGERPRINT_KEY_B64`, `GRIDLY_ENTITLEMENT_SIGNING_PKCS8_B64`, `GRIDLY_GOOGLE_SERVICE_ACCOUNT_JSON`, `SUPABASE_SERVICE_ROLE_KEY`, `SUPABASE_URL`, `GRIDLY_STORE_ENVIRONMENT`, `GRIDLY_STORE_BUNDLE_ID`. No client/Worker gets AES/service/account material. Exact Worker future binding **names only**: `SUBSCRIPTION_OPS_URL`, `GRIDLY_SUBSCRIPTION_OPS_TOKEN`, `SUBSCRIPTION_DEADMAN_PING_URL`, and existing `ALERT_STATE`, `RESEND_API_KEY`, `ALERT_FROM`, `ALERT_TO`. Edge endpoint must hold its corresponding separate `GRIDLY_SUBSCRIPTION_OPS_TOKEN`. Do NOT reuse read-only `GRIDLY_MONITOR_TOKEN` as a mutation capability.

Raw Google token exists transiently in native/store/client-server request memory, server decrypt memory and Google's token-bearing API URL; never persisted as plaintext in proposed Gridly DB or returned in public HTTP. Source catches provider errors to bounded categories, does not log token, and HTTP health/Worker reconstruct allowlisted fields. External proxy/provider trace/body/URL and WAL/backup retention need final configuration review. HMAC fingerprint is sensitive linkage, not anonymous.

## 5. Exact queue state machine and entitlement effect

Fresh trusted Google provider result → bounded normalized cache → seal with CURRENT → enqueue `(environment,fingerprint)` PK, queued, absolute expiry. Duplicate conflict does not update ciphertext/key/expiry. Targeted ensure or minute internal retry claims <=10 due rows with SKIP LOCKED, fresh UUID lease 60sec, attempts capped1m. Server decrypts by exact key version, re-verifies provider, reconciles cache, only ACKs if still entitled/required/inside deadline and >9sec lease safety margin. Provider already ACKNOWLEDGED skips POST. Success deletes row under live lease. Terminal result deletes row + aggregate; retryable provider/credential/cache error clears lease, sets `retry` +1min, retains SAME expiry. Worker crash/expired lease permits new UUID claim; old resolve fails. External old-worker POST cannot be transactionally fenced; abort signal and pre-ACK lease margin reduce overlap, and fresh GET makes response-loss replay safe, but real provider concurrency acceptance still required. At expiry, independent SQL purge removes <=500/environment/call without AES/Google/Edge credentials. Oldest pending age uses the environment/created_at index and LIMIT 1; returned age is capped 3600 seconds. Purge records expiry/terminal aggregate and last purge UTC in same transaction. SQL housekeeping runs cache prune too; a failure rolls back both and is visible as stale purge time. **No request/cache/queued hint grants new authority**; ensure requires success and fresh post-ACK Google verification before signing. Confirmed provider denial overrides cache; existing LP244.65 signed native continuity remains separate and unchanged.

Apple retains its existing StoreKit verification → entitlement/service delivery → transaction.finish architecture. No symmetric backend Apple queue or raw signed transaction persistence is added.
