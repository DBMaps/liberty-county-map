# Gridly Satellite Labels: isolated HTTPS gateway

Stage 3D is a local deployment package for a **dedicated nonproduction project**. The Edge entrypoint deliberately has no Apple eligibility or App Attest adapter wired. Both runtime switches default off, the database defaults disabled, and there is no client fixture mode or production fallback. Do not link this directory to an existing Gridly project. No CLI deploy command has been run.

See [fixed-path wire and privacy](FIXED-PATH-PRIVACY.md) and [Stage 3E hosting readiness](HOSTING-READINESS.md) for hosted privacy gates, sizing, recovery, and the separate approval sequence.

## Source and runtime

- Certified source: `86ecf2b9e2257ea733177a391397a084c7706a08`, [certification run 43446641110](https://github.com/DBMaps/liberty-county-map/actions/runs/43446641110). `foundation.sha256` pins five byte-identical JavaScript modules and the original SQL. `verify-sources.mjs` checks the copies, originals, and generated gateway seam. Only P-256 SPKI import and P1363 verification use Web Crypto in the Edge port because Deno's Node shim differs. The certified GET contract remains intact in the foundation; the Edge port now uses the isolated fixed POST proof. Existing iOS transport and handler stay in their certified source tree.
- HTTPS ingress sees the **original** request target, rejects ambiguous paths and unexpected methods, throttles by observed source, discards incoming forwarding and ingress headers, and injects a secret server-only ingress header. `ingress.nginx.conf.example` is a draft; render it with a dedicated hostname, certificates, project ref, and secret include. The native client never receives the ingress key. Limit by actual peer IP (or a verified front load balancer); never trust a public forwarded IP header. Bound ingress instance count and set platform-wide abuse limits.
- The client signs the public HTTPS origin, the fixed `POST /v1/imagery-labels/tile` target, and the digest of the canonical JSON body. The ingress maps only that route, `POST /v1/labels/challenge`, `POST /v1/labels/lease`, and `GET /health` to the function. The Edge validates the canonical target again; raw request-target validation must happen **before** the Fetch API normalizes dot segments. Direct calls to the platform URL cannot get past the ingress gate on private routes. `/health` returns reachability only. It does not establish database, verifier, or provider readiness.
- Supabase platform JWT checking is disabled **only for this function** because it uses trusted ingress plus the certified native proof contract. See [Supabase Edge authentication](https://supabase.com/docs/guides/functions/auth) and [Postgres connection options](https://supabase.com/docs/guides/functions/connect-to-postgres). Browser CORS is disabled and no Referer is used as proof. Use TLS from iOS to ingress, ingress to Supabase with upstream certificate and hostname validation, and Edge to Postgres with certificate validation.
- Successful tile responses contain verified PNG bytes only. Responses use `no-store`; there is no shared tile cache or per-user response sharing. Each admitted request consumes its own quota. On interruption, the client treats the overlay as unavailable; base imagery remains independent. No automatic redirect or retry goes upstream.

## Admission and database

1. The server issues a random, two-minute challenge and stores it in Postgres. Expired or unknown challenges are denied before verifier calls. The challenge is consumed atomically with the lease decision; concurrent requests may reach the trusted verifier, but cannot issue two leases. The App Attest adapter must atomically validate and advance its own assertion counter.
2. Wire both server-owned ports in `index.ts` only after separate review. Apple must verify signed evidence and certificate chain, expected issuer/audience or Appleâ€™s corresponding bundle/app identifiers, product, sandbox environment, freshness, expiry, revocation, and paid period. App Attest must verify Apple trust/attestation and stored key state, the pilot app and production App Attest environment, challenge expiry, counter, installation, and the certified binding over purpose, challenge, both environments, paid evidence hash and labels P-256 key fingerprint. Supply stable opaque installation and purchase-lineage identifiers. A client-declared paid or integrity result is never authoritative. The database role trusts only the dedicated server to call admission; do not distribute its credential to clients.
3. A lease lasts at most five minutes and no longer than verified paid eligibility. Bind it to the verified installation and labels key. Each tile requires a valid P-256 signature over its canonical target, lease, timestamp and request UUID. The database serializes reservation, rejects replay and cross-install key reassignment while a lease remains, and checks expiry/revocation before reservation and before successful delivery. Adapters must enforce stable, attested installation-to-key mapping across renewals.
4. Apply both migration drafts in order, only to the isolated database and as the migration owner. Provision a credential for the dedicated `label_pilot_runtime` role; never use the migration owner, public API roles, service-role key or reporting database. Do not expose `label_pilot` through PostgREST. Keep revocation, disable and cleanup functions owner-only. The connector requires the isolated direct DB endpoint; verify IPv6, connection budgets and certificate trust in that runtime before enabling. Do not fall back to a production endpoint or disable certificate verification.
5. Expired leases (and associated replay IDs), used challenges, ingress histories and UTC usage counters are reaped by DB-clock state transitions. Schedule the owner-only `label_pilot.cleanup_expired()` in an isolated scheduler if approved. Unknown dispatches after process loss retain slots intentionally. Reconcile only after disabling, draining and proving the relevant transport is no longer active. Never refund uncertain requests or reset replay records to restore capacity.

## Limits and activation

| Control | Default |
| --- | --- |
| Attempts / UTC day | 500 per installation, 1,000 per purchase lineage, 10,000 aggregate |
| Verified traffic and active reservations | 60/minute and 4 active per installation; 64 active aggregate |
| Ingress | 240/minute aggregate in Postgres; proxy draft adds 10/s per source, burst 16, 8 connections per source |
| OAuth | One in-flight refresh per Edge isolate, 5 s minimum interval, plus 12 attempts/minute globally in Postgres |
| Time and payload | 6 s end-to-end, 2 s OAuth, 3 s tile; 512 KiB hard upstream PNG cap and configurable response cap up to that bound |
| Other limits | 32 Edge requests active per isolate; 48 KiB lease body; 1,024 pending challenges |

DB knobs are constrained columns on `label_pilot.control` and can be lowered by the owner. Budgets charge **attempts** once, conservatively before dispatch. Fixed-minute ingress and OAuth limits allow bursts across a minute boundary. Per-installation rate uses a rolling minute. A kill switch blocks new admissions, reservations and provider dispatch checks; requests already dispatched cannot be undone. Deno isolates do not share bearer tokens. Confirm per-replica connections, refresh behavior and aggregate provider metrics before scaling.

`.env.example` lists operator settings. Secret store inventory: `GRIDLY_LABELS_DATABASE_URL`, `GRIDLY_LABELS_DATABASE_CA_PEM` (the isolated project's public CA trust material), `GRIDLY_LABELS_INGRESS_KEY`, `GRIDLY_LABELS_ESRI_CLIENT_ID`, `GRIDLY_LABELS_ESRI_CLIENT_SECRET`. Use the same randomly generated ingress key at the trusted ingress and function; keep the proxy include private. Apple adapter secret names are intentionally deferred until the verifier design is reviewed. The certified Esri adapter uses `client_credentials` at `www.arcgis.com` and the fixed Imagery Labels tile route at `static-map-tiles-api.arcgis.com`, with an Authorization bearer header, bounded responses, token lifetime from `expires_in`, no fabricated Referer and no token in a URL. Do not reuse either consumer key.

## Kill switch and rollback

Close ingress; set `GRIDLY_LABELS_ESRI_ENABLED=false` and `GRIDLY_LABELS_PILOT_ENABLED=false`; as isolated database owner run `select label_pilot.pilot_disable();` to atomically disable, revoke leases, and clear pending challenges. Verify aggregate outbound counts stop increasing after in-flight work drains. If necessary, remove the isolated function and its secrets under separate approval. Retain private audit counters and do not touch production. To recover, review cause, reconcile state with egress stopped, redeploy a reviewed disabled revision, repeat synthetic checks, then seek explicit reactivation approval.

The extra HTTPS hop and several DB checks can delay first labels; cold starts, token refresh and network latency are unmeasured. The existing native overlay can keep imagery usable independently of labels. Stage 3D does not certify Build 19 integration, fix Build 18, or change November 30 rollover exposure for customers still on the original key.

Local Windows sample (Deno 2.6.8, PostgreSQL 17): challenge plus lease took 1.73 ms, and median invalid proof, successful Fetch tile, and synthetic provider failure took 1.50, 5.04 and 1.78 ms respectively. The Fetch sample made 24 synthetic tile calls and reused one token. A separate Node 24.17 foundation run handled 400 successful tiles (p50 10.40 ms, p95 21.02 ms), peaked at four active tile calls, and reused one token across 403 attempts. Cancellation returned in 2.64 ms; after GC the measured heap/RSS deltas were +1.83 MB/+48.50 MB (one run, not a leak test). One database reservation took 30.158 ms inside PostgreSQL; 12 concurrent loopback clients completed in 652.3 ms including process and connection setup. None of these are hosted or Esri latency estimates.
