# LP209.1 Road Candidate Awareness Hoist Regression Closure

## Reproduction and classification

The exact five-test LP209 closure command reproduced one failure at
`v947RoadCandidateAwarenessHoist.test.js:57`. The assertion expected the body
reported as `resolveGridlyAwarenessArea` to contain
`const normalizedCandidateLookup = new Map();`; the assertion result was
`actual: false`, `expected: true`.

This was a static-source-inspection failure, not an executed runtime failure.
The test helper searched for the prefix `function resolveGridlyAwarenessArea`.
That prefix first matched `resolveGridlyAwarenessAreaQuery`, which occurs before
the intended `resolveGridlyAwarenessArea` declaration. The helper therefore
extracted the wrong function body. The first incorrect condition was the
test-local declaration marker, not a production resolver condition.

Both declarations and the defective prefix-matching test shipped in the
repository baseline commit `b684ea0`, before every LP209 commit. `git blame`
attributes both resolver declarations and the caching implementation to that
baseline. The LP209 commit range did not change `js/app.js` or the v947 test.
The failure therefore predates LP209, and the history evidence proves the
specific mechanism rather than merely labeling it pre-existing.

## Production truth and repair

The intended production function already normalizes the input once, caches
normalized candidate `label` and `storageValue` values in a per-resolution
`Map`, and reuses those normalized values while resolving county-wide and
community candidates. The governed normalized lookup representation is a
lowercase, apostrophe-free, ampersand-expanded (`and`), alphanumeric,
single-space-trimmed string; a dashed form is derived only for canonical key
matching.

The repair makes the test helper match the complete declaration token,
including `(`. No production file, runtime manifest, roadway package, LP209
evidence, or owner-local artifact is changed.

## Awareness hoist contract

The relevant production and regression coverage establishes this contract:

- One immutable road-evaluation operation context carries the selected
  awareness-area object, canonical active county id, county display context,
  normalized awareness lookup, and invalid-label policy into candidate
  evaluation.
- Candidate scans and nearest-road pair resolution reuse that context rather
  than resolving or broadening awareness/county scope per candidate.
- Candidate roadway geometry remains bound to the active county's configured
  source. A county transition clears prior geometry before replacement or on a
  failed load, so no stale candidate can survive the transition.
- A loaded-package cache is valid only when its loaded county equals the active
  roadway source county. This preserves county ownership and package
  provenance and prevents cross-county nearest-road association.
- The selected PLACE/community awareness object is retained in the operation
  context; it is not reduced to, or overwritten by, a legacy road seed.
- Availability of additional candidate packages does not make them runtime
  visible. Selection remains constrained by active-county activation and the
  unchanged 28-county production runtime manifest.

## LP209 non-regression and gate

The four protected LP209 evidence files remain byte-for-byte untouched.
Statewide manufacturing was not rerun, no roadway package was published or
activated, and LP209 readiness was not altered. Portable LP209 verification,
LP209 tests, the targeted roadway/awareness regressions, manifest SHA-256, and
the 28-county runtime count are the publication-gate evidence.
