# Dispatch invitation delivery — local-only adapter

DAYTON-INVITE-01-v1 implementation. No real credentials, provider requests, invitations, email, production access or deployment. Install `invitation-delivery.local.sql` only after the marked empty Phase 29 disposable installation. It is not a production forward migration. `run-certification.ps1` uses the existing guarded TEMP Supabase project; it never runs CLI commands from this repository.

The server-only `InvitationDelivery` exposes sendInvitation, sendReissue, recordProviderEvent and discloseFallback. Repository, authenticated operator authorization, verified recipient resolution and transport are explicit server-owned ports. Core lifecycle does not know Resend request shapes. ResendAdapter renders the provider request and only returns bounded success/failure plus validated message ID. It has no built-in fetch/network transport; certification supplies a deterministic fake. Credentials and transport are private fields. TEST rejects credentials and non-.invalid recipients; provider/service environments must match. Browser execution is refused. Real hosting, network transport, secret provisioning, webhook registration and actual approved production routes are intentionally not configured by this local implementation.

Exact sender and production origin are constants. Server constructs links from explicitly configured acceptance/support paths and same-origin redirect path list. Paths cannot contain queries, fragments, authority overrides, traversal, wildcards or percent-encoded destinations. Certification paths are explicitly synthetic and confer no approval on production routes. Verified recipient resolver binds target user identity to the delivery address; callers cannot provide destination email, origin, expiry, return URL, subject or operational content. Purpose is fixed and organization/unit labels are bounded. The database checks members.invite and explicit unit access when unit context is supplied; client/operator callbacks never substitute for those live checks.

The original organization_invitations table is authoritative. Server issuance uses now + 168 hours; all caller duration overrides are rejected. Legacy invite_member is refused by report_execute, preventing shorter/longer legacy issuance bypass. Prior-token revocation, new identity, digest, delivery-attempt lineage and secret-free audit commit atomically. Existing identity-bound acceptance/revocation commands remain. An authorized identical acceptance receipt replay remains an idempotent result, not a second token use/membership; fresh reuse is refused.

Tokens exist only in transient server memory and the actual message or one-time manual return. SHA-256 token digest is stored in the existing invitation table. No raw-token outbox or retry retrieval exists. Email send claim is durable and one-time; it rechecks pending/unexpired invitation, active organization, issuing operator eligibility and recipient suppression before transport. A crash/ambiguous send cannot safely recover a token: require explicit operator reissue instead of blind retries. Pending/SENDING delivery may need operator recovery; do not claim exactly-once network delivery. Reissue consumes the supplied prior revision. Manual fallback is explicitly authorized replacement issuance with recipient confirmation, reason category and disclosure evidence committed before the link is returned. It never changes the default EMAIL delivery mode. A response lost after commit cannot be recovered; repeated request/prior revision is refused, and recovery requires another authorized replacement.

Four new forced-RLS tables: invitation_delivery_attempts, invitation_provider_events, invitation_delivery_suppressions (dispatch_private), invitation_delivery_events (dispatch_audit). They contain non-secret correlation, status, opaque actor/recipient tokens and bounded categories; events/audit are append-only. New private functions: invitation_issue, invitation_suppress, invitation_claim_send, invitation_transport_result. Two invoker RPCs: issue_dispatch_invitation and set_delivery_suppression. Existing command owner remains NOLOGIN/BYPASSRLS with unchanged role attributes. New dispatch_delivery_transport is NOLOGIN/NOINHERIT/NOBYPASSRLS, with only private-schema usage and claim/result EXECUTE; no table or Auth access, browser membership or broad service_role grant. No extra postgres Auth bridge is added. The existing RPC invitation acceptance path still uses fresh AAL2/TOTP and live identity checks.

Webhook verifier uses the server-held decoded signing secret, raw body and Svix ID/timestamp/signature with HMAC-SHA256, constant-time comparison and a five-minute replay window. Request input cannot supply its own signing secret or clock. Persistence accepts only allowlisted non-secret fields; no raw webhook body is stored. Event IDs deduplicate; changed-content duplicate refuses. Unknown message correlation refuses for provider retry, without fabricating invitation state. Adverse status has precedence over late success. Hard bounce and complaint activate delivery-only suppression; explicit members.invite action clears or applies manual suppression with audit. Neither delivery nor suppression grants/revokes membership, capabilities or reviewer authority. The trusted server role must only receive verified events; it is not exposed as an unauthenticated browser API.

DAYTON-RETENTION-01 remains the policy baseline. Attempts follow invitation/receipt evidence windows; security/remediation audit follows its 7-year category. Recipient identity mappings can be retired without losing opaque evidence. No disposition jobs, legal holds, backup-aging changes or restore controls are implemented here; those previously recorded gaps remain. Provider-side message retention and token-bearing bodies must be reviewed before real activation. No legal/privacy certification is claimed.

Relevant provider references: https://resend.com/docs/api-reference/emails/send-email and https://resend.com/docs/webhooks/verify-webhooks-requests. No SDK dependency or repository-wide configuration was changed.
